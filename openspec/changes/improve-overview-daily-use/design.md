## Context

基线为 `dc8e7e095efcde6b78c4a1088e2ab0b4808476f6`。当前 ServiceList 无条件展开所有服务；Overview、IncidentList 和 OperationAttentionCard 各自读取数据，没有轮询，顶部按钮只刷新资源快照。

## Goals / Non-Goals

**Goals:** 六项分页和可搜索服务；三类当前查询每 30 秒更新；失败、恢复、输入保持和窄屏行为可验证。

**Non-Goals:** 不改后端采集、API、依赖、全局查询配置或其他页面；不改变授权、模型调用、短期上下文和长期记忆，不做真实节点验证或外部图纸。

## Decisions

- 在 ServiceList 中保留搜索词与页码，按名称、端口、地址和完整节点标识进行不区分大小写的子串过滤，再切片。搜索变化回到第一页；数据减少时把页码收敛到最后有效页。原数组和逐条证据保持不变。现有合同最多 1024 项，本地过滤足够，不引入虚拟列表或服务端分页。
- 三个 `useQuery` 使用相同 30 秒间隔和 `refetchIntervalInBackground: false`，由 TanStack Query 管理可见性和卸载。通过总览专用查询标记选择当前活跃查询，顶部刷新复用 `refetchQueries`，刷新状态覆盖三类请求；不调整 AppProviders。
- 资源失败沿用旧快照警告，详情有缓存时明确标为旧详情且保留输入；待办失败沿用独立不可用状态。错误时不从旧详情提供候选操作交接。查询更新不重建表单或重置搜索。
- API 读取核对：资源路由调用 OverviewService.view 聚合本机配置、缓存与快照；incident GET 读取存储，建议问题由固定模板生成；operations GET 读取本机目标端摘要和请求端存储。刷新只调用这三个 GET，不调用 operation 的 POST refresh，也不触发 follow-up 或模型推理。
- 组件测试用现有 fetch mock；浏览器通过路由 fixture 隔离真实服务和模型，用浏览器时钟验证定时更新。Windows Chromium 与 WebKit 使用同一代码与布局；本地可用浏览器作为证据，实际 macOS 门禁仍由后续环境验证。

## Risks / Trade-offs

- 30 秒刷新不是实时推送 → 继续显示服务端证据时间、新鲜度和失败警告，允许手动刷新。
- 服务增减会改变当前页内容 → 保留搜索、限制有效页码并显示范围，不改变服务排序或删除数据。
- 多卡片请求独立成功或失败 → 每类维持独立错误状态，不把部分成功视为全页实时。
- 隐藏期间已发出的请求可能完成 → 不取消有效读取，隐藏时不新发周期请求，返回页面恢复轮询。
