## Why

2026-09-07 的固定真实事故矩阵证明当前 Qwen 调查会在没有工具证据时提前停止，或只拿到一项只读结果就尝试确认根因，导致 12 个场景仅 3 个完整通过且出现 3 次无依据确认尝试。用户现在能看到 incident，却还不能稳定得到“围绕信息缺口取证并收敛”的可信调查结果，因此尚不能进入处理计划与本地审批阶段。

## What Changes

- 为每类本机 incident 定义最小、公开且与事件相关的证据路径；每轮只向模型暴露当前能填补信息缺口的既有只读工具，并公开记录剩余缺口。
- 当模型忽略必需工具、过早返回终态或遗漏已有证据引用时，在现有轮次和调用预算内进行有界纠正；仍不合规时只允许受控只读 fallback 或保守终止，不伪造结论。
- 只有事件所需证据均成功取得并被终态引用、且不存在冲突时才允许确认；必要工具失败、证据冲突或预算不足分别稳定落为 `insufficient_evidence` 或 `budget_exhausted`。
- 对陈旧状态直接保留确定性差异与信息不可用结论；远端、Coordinator 目录和聚合来源继续不暴露、不执行当前节点的本机工具。
- 更新并版本化事故调查提示，使用同一套不泄露评分答案的固定矩阵重跑真实 Qwen；只有安全门禁全绿且五项质量指标达标，才允许下一阶段接入处理计划与本地审批。
- 非目标：不实现任何写操作、自动修复或操作审批，不接入 DeepSeek 密钥，不恢复 packet relay、复杂 Provider、复杂自动组网、showcase 或 Linux 节点，不修改 WireGuard、防火墙、路由、DNS、生产服务及现有模型服务。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `autonomous-incident-investigation`: 把现有一次性“模型选工具或结束”收紧为信息缺口驱动、可纠正、按事件证据门槛收敛的只读调查循环。

## Impact

- 影响事故调查循环、版本化 Prompt、公开调查轨迹及其回归测试。
- 复用现有 Context Runtime、Tool Runtime、六个只读工具、预算和持久化合同；不新增依赖，不改变公开 API 或数据库格式。
- 新增本阶段真实 Qwen 验收证据；历史基准和数据集保持不可变，便于前后对比。
