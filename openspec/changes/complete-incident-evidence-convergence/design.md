## Context

现有 `IncidentInvestigator` 首轮依赖 Provider 的 `tool_choice=required`，但兼容后端可以返回合法终态而不调用工具；除 `service_added` 外，这类响应会立即结束调查。执行一次工具后，Runtime 又只检查“是否引用过任意一项工具证据”，没有检查当前事件仍缺哪些证据，因此 Qwen 会用零到一项结果提前停止或尝试确认。2026-09-07 的真实固定矩阵得到根因成功率 0、工具选择率 0.2222、任务完成率 0.25 和无依据断言率 0.25，证明这是生产循环缺口，不是单次采样噪声。

本阶段只处理本机、只读、隔离调查。模型继续负责候选解释和在当前允许集合中选择下一项工具；确定性 Runtime 负责事件证据策略、工具依赖、预算、安全边界和最终确认门槛。工具结果仍是实时短期上下文，不写入长期记忆；任何有副作用操作仍完全位于调查边界之外。

## Goals / Non-Goals

**Goals:**

- 让本机 incident 围绕公开信息缺口持续取证，不再接受零工具提前终止。
- 只暴露与事件相关且当前参数可确定的既有只读工具，减少无关选择和无效参数。
- 证据路径、纠正、fallback、工具失败、冲突和预算终态全部可测试、可持久化、可审计。
- 确认结论必须引用当前事件要求的全部成功工具证据；不足时不得把模型常识升级为事实。
- 用固定场景和真实 Qwen 证明安全及质量门槛，再决定是否进入操作计划阶段。

**Non-Goals:**

- 不新增工具、Planner 框架、Provider 抽象、长期记忆或数据库字段。
- 不实现写操作、自动修复、审批、执行、验证或回滚。
- 不连接 DeepSeek、不读取或迁移密钥，不改变现有模型服务进程。
- 不处理 packet relay、复杂自动组网、showcase、Linux、WireGuard、防火墙、路由或 DNS。

## Decisions

1. **用事件级证据路径表达产品规则，不读取评测答案。** 本机 `service_added` 需要监听与进程证据，`service_removed` 需要进程与 Docker 生命周期证据，`node_offline` 需要节点与 WireGuard 证据，`local_only` 需要节点、监听与目标可达性证据，`remote_unreachable` 需要节点、WireGuard 与目标可达性证据；`state_stale` 因当前事实本身已陈旧，直接以信息不可用收口。该映射来自事件语义并位于生产 Runtime，评测字段 `required_tools`、期望根因和场景 ID 仍不会进入模型上下文。相比“任意一项工具就够”，固定路径能给确认门槛；相比新增通用 Planner，它只需一个小型映射和现有循环。

2. **模型只在当前信息缺口对应的工具集合中动态选择。** Runtime 每轮生成公开状态，包含事件、已尝试工具、成功证据引用、剩余信息缺口和本轮允许工具。可达性探测只有在成功读取节点摘要、获得目标地址后才开放；Runtime 把该地址与 incident 端口作为本轮可信参数约束交给 Tool Runtime，不匹配时按无效参数拒绝且不执行适配器。其余事件相关工具可由模型决定先后。系统提示明确：剩余缺口非空时必须调用本轮工具，不得返回终态。未相关的六工具子集不暴露，Shell、Python、写工具和未知工具仍由既有边界拒绝。

3. **一次模型纠正后才使用确定性 fallback。** 当本轮仍有缺口而模型未调用工具时，Runtime 不保存模型正文或隐藏推理，只公开记录一次合同违例并用相同允许集合重试。整个调查只提供一次模型纠正机会；再次违例时，Runtime 选择证据路径中第一个当前可用工具，经同一 Tool Runtime 执行。这样优先保留真实模型路由能力，又确保兼容后端忽略 `tool_choice` 时用户仍能取得安全只读证据；fallback 必须在评测中单独计数，不能冒充模型选择。

4. **工具失败和预算由 Runtime 直接裁决。** 必要工具返回失败、拒绝或无效参数时，必要信息已不可获得，Runtime 立即生成 `insufficient_evidence`；已有成功工具仍留在公开轨迹。若仍有缺口但工具调用预算已满，则直接生成 `budget_exhausted`，不再请求模型给出可能越界的终态。Provider 不可用继续沿用现有 `investigation_unavailable`。

5. **最终确认同时校验覆盖和引用。** 所有事件所需工具必须成功，且模型的 supported hypothesis、facts 或 conclusion 必须引用这些真实 `toolrun_...`。模型在缺口未清空时返回终态会继续取证；缺口已清空但遗漏引用时允许一次独立的终态格式纠正。第二次仍不满足门槛则保留无依据尝试并降级为 `insufficient_evidence`。模型返回引用真实证据的冲突或未知结论时允许安全结束，不强行确认。

6. **公开信息缺口复用现有 trace，不扩展持久化合同。** 每次工具选择、合同纠正、剩余缺口变化和最终报告写入现有 `PublicTraceEntry`；候选假设仍由现有 `IncidentHypothesis` 保存，最终结构化决定更新状态和证据。不新增数据库迁移或只使用一次的新抽象。

7. **Prompt 变更必须版本化，历史基准保持不可变。** 生产事故 Prompt 升级到新版本，明确事件语义、信息缺口和证据引用规则。复制现有 v3 场景为下一数据集版本，保留场景、夹具和期望结果，只把依赖“停止、离线、远端、失败”等特定中文措辞的评分词替换为工具证据中的稳定对象、状态、地址和端口；v3 和 2026-09-07 报告保持原样。正式报告必须记录精确模型路径、Provider、Prompt、工具版本、数据集哈希、代码提交及模型服务前后健康状态。

## Risks / Trade-offs

- [固定证据路径可能多调用一次与最终根因无关的只读工具] → 每类事件只保留最小区分集合，并以不必要工具调用率不高于 0.25 验收；以后只有真实数据证明某项长期无价值时才收缩。
- [模型连续忽略工具合同] → 只给一次纠正，然后使用已审计的确定性 fallback；仍按模型选择与 fallback 分开计数。
- [模型拿齐证据仍不能写出合格结论] → 允许一次终态引用纠正，失败后如实降级，不由 Runtime 拼造根因。
- [探测参数依赖节点摘要] → 未成功取得地址前不开放探测工具；不猜测地址，不从评分夹具注入参数。
- [Qwen 延迟或内存压力增加] → 复用现有最多 6 轮和 8 次工具预算；真实验收同时记录延迟与 token，上限不够时优先减少无价值轮次而不是无限扩容。
- [远端 incident 无法用本机证据闭环] → 继续允许合法的 evidence-free `insufficient_evidence`，等待未来真实跨节点工具，不拿当前机器结果冒充。

## Migration Plan

无数据或 API 迁移。发布后新调查自动使用证据路径；已完成 incident 保持原报告，中断 incident 仍需显式恢复。回滚恢复上一版本代码即可，SQLite 合同不变。
