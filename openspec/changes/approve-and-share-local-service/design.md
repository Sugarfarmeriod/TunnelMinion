## Context

当前 TunnelMinion 已在固定 Windows A 与 macOS B 之间完成只读诊断：Agent 能识别远端服务、监听范围和不可达原因，但不能改变系统。下一条产品闭环需要处理“已确认服务只监听本机，用户希望让指定 peer 临时访问”的场景。

这是首个有副作用的能力。模型、请求节点、目标节点、平台适配器和恢复进程之间必须有稳定状态与明确所有权，且任何失败都不能修改或删除用户原有的 WireGuard、路由、服务或容器配置。当前产品仍以单所有者私有网络为正式目标；多人家庭/实验室和企业受管部署只保留权限边界，不在本 change 实现。

## Goals / Non-Goals

**Goals:**

- 在现有 A/B WireGuard 网络中完成“诊断 → 计划 → 授权 → 临时共享 → 请求节点验证 → 到期撤销”的纵向闭环。
- 定义 L0～L4 操作等级，使只读工具、低风险可逆操作、敏感操作和禁止操作由确定性策略区分。
- 默认要求用户批准 L2 写操作，同时允许节点所有者建立范围有限、可撤销、可过期的预授权。
- 所有写操作具备幂等键、资源所有权、执行后验证、失败回滚、重启恢复和关联审计。
- 第一版提供适合浏览器访问的 HTTP/HTTPS 服务共享，并为后续受支持 TCP 服务保留适配器边界。

**Non-Goals:**

- 不公开服务到互联网，不提供公网穿透或公共 SaaS 中继。
- 不修改被共享服务本身，不重启服务、不控制 Docker、不修改用户 WireGuard、路由或防火墙配置。
- 不提供任意端口转发、任意 Shell/Python、任意文件访问或模型生成代码执行。
- 不实现 Coordinator、多租户、企业 RBAC、自动组网、Linux Provider 或完整独立 React 前端。
- 不实现多 Agent、自主修改代码、跨节点 Playbook 检索或基于历史成功记录自动扩大权限。

## Decisions

### 1. 使用“临时共享本机服务”作为产品术语

“发布”容易被理解为软件发布或互联网暴露。本 change 将共享定义为：在目标节点已有 WireGuard 私网地址上创建由 TunnelMinion 管理的临时入口，把指定 peer 的请求转发到已确认的本机服务；入口有访问范围和过期时间，且不修改目标服务。

被否决的方案：直接把服务监听地址从 `127.0.0.1` 改为 WireGuard 地址。该方案依赖服务配置格式和重启方式，回滚风险高，也会突破“只管理自有资源”的边界。

### 2. 目标节点策略引擎拥有最终授权权

操作等级定义如下：

| 等级 | 含义 | 默认行为 |
|---|---|---|
| L0 | 只读观察 | Agent 可自动调用 |
| L1 | 无副作用建议或计划 | 可自动生成，不执行写操作 |
| L2 | 低风险、限时、可逆且可验证的操作 | 默认逐次批准；可由节点所有者预授权 |
| L3 | 服务重启、容器控制、网络配置等敏感操作 | 本 change 不实现，后续仍应逐次批准 |
| L4 | 任意代码、秘密读取、删除未知资源等禁止操作 | 始终拒绝 |

授权决策只能由目标节点的确定性策略引擎作出。模型可以生成计划和说明，但不能批准计划、创建预授权或提高操作等级。

L2 预授权必须同时限制请求 peer、工具、目标服务或服务选择条件、最长持续时间、端口范围和有效期。预授权默认不存在，可以撤销，命中时仍需生成审计事件并向节点所有者展示结果。

被否决的方案：仅通过“两个节点是否属于同一个人”决定自动执行。所有权难以由模型可靠推断，且同一所有者也不能消除错误目标、过期状态和重复执行风险。

### 3. 使用持久化操作状态机隔离模型与副作用

操作记录至少包含 `operation_id`、`plan_version`、请求与目标节点、目标服务证据、风险等级、预期变化、授权依据、幂等键、租约、执行资源、验证结果、回滚结果和关联 run/tool run ID。

状态机采用：

```text
planned
  → awaiting_authorization
  → authorized
  → executing
  → verifying
  → succeeded
  → expiring
  → expired
```

任一步失败进入 `rolling_back`，最终为 `rolled_back` 或需要人工处理的 `cleanup_failed`。拒绝、取消和授权过期分别使用终态，不能复用普通工具成功/失败状态。

模型只产生结构化候选计划。服务端重新读取实时状态并验证计划版本、目标服务、授权和预算后，才把操作交给固定适配器。

### 4. 第一条实现路径以 HTTP 临时反向代理为主

首个适配器在目标节点创建独立的临时 HTTP 入口，只绑定显式 WireGuard 地址和受控端口，转发到已验证的本机 HTTP 服务。入口使用短期高熵访问令牌，并限制已配置请求 peer；响应和日志不得泄露令牌。

具体跨平台代理实现需要在编码前进行最小技术验证，比较 Python 内嵌代理与受管外部代理的可打包性、取消、连接排空和清理行为。未完成验证前不把具体依赖写成既定选择。

HTTPS 上游证书验证和非 HTTP TCP 共享属于受支持能力扩展：接口可以预留，但第一条 A/B 验收不得依赖任意 TCP 转发。

被否决的方案：修改系统防火墙或创建通用系统级端口转发。该方案权限高、平台差异大且难以证明不会影响现有规则。

### 5. 以租约、幂等和自有资源清单控制生命周期

每次共享都有开始时间、绝对过期时间和最大持续时间。相同幂等键的重复请求返回同一操作，不创建第二个入口。平台适配器在创建资源后立即记录不可变资源指纹，只允许删除该操作创建且指纹仍匹配的资源。

Agent 重启后，恢复器读取未终结操作：

- 已过期的入口优先清理；
- 未完成执行不自动重放；
- 无法证明所有权的资源不删除，标记 `cleanup_failed`；
- 控制面短时离线不延长绝对过期时间。

### 6. 成功必须由请求节点独立验证

目标节点报告“代理已启动”只表示执行阶段成功。请求节点必须携带本次临时凭据，从实际访问路径发起受预算约束的探测；只有返回符合计划中健康判据的结果，操作才能进入 `succeeded`。

验证失败、超时、请求节点离线或证据不一致时，目标节点撤销本次入口。撤销本身失败时保留诊断证据并向本地页面显示人工清理建议。

### 7. 本地页面展示授权与完整状态，不重写前端

现有内嵌本地页面新增计划、风险等级、授权范围、批准/拒绝、执行、验证、撤销和到期视图。页面只调用本机 Agent API；远端计划文本按不可信内容渲染。

第一版不要求独立 React 应用。成熟交互与产品化前端在后续 change 中处理。

### 8. 为经验证 Playbook 保留结构化结果，但不自动学习

成功和失败记录保留适用条件、观察证据、确定性动作、验证和回滚结果，后续可以抽取为版本化 Playbook。Playbook 检索可以采用 RAG 思路，但本 change 不建立向量库、不跨节点分享经验，也不允许历史成功记录绕过当前授权。

### 9. 候选计划使用最小、可追踪且以实时证据为先的上下文

Agent 只在用户已表达明确共享意图、只读诊断已得到足够证据时生成候选计划。计划输入由当前意图、最新已验证的节点与服务证据、允许使用的工具 schema 和必要的安全约束组成；历史对话、摘要、记忆与模型推断只能帮助解释，不能覆盖实时证据。若二者冲突，系统必须保留实时证据并把冲突暴露为需要重新确认或重新诊断的状态。

候选计划必须展示目标服务及证据、请求与目标节点、端口、持续时间、风险等级、预期变化、验证方法和回滚方法。模型输出只是一份不具备权限的候选数据：模型不能批准计划、创建或修改预授权、降低确定性策略给出的等级，也不能直接持有写适配器。服务端在创建可授权操作前重新校验 schema、证据引用、计划版本、服务指纹、授权范围和预算。

每次计划生成记录脱敏的 `prompt_id`、`prompt_version`、模型与 provider 标识、工具 schema 版本、证据快照版本，以及上下文中消息、工具、结果、证据与被裁剪内容的数量和大小。日志不得包含完整凭据、认证头或不必要的远端正文。这些字段用于复现与区分“上下文组装错误、模型或 prompt 错误、工具或 Harness 错误、授权治理错误”，不把 prompt 长度、Agent 数量或所谓 Harness 层数当作完成度。

模型 Provider 或候选计划上下文组装失败时，只阻止新的 AI 候选计划生成。已有操作的批准、拒绝、取消、主动撤销、租约过期、恢复和清理仍由确定性服务端路径工作；系统不得因模型恢复而自动重放失败的计划生成或写操作。

## Risks / Trade-offs

- [临时入口仍扩大服务攻击面] → 只绑定 WireGuard 地址，限制请求 peer、端口、时长和令牌，并在请求节点完成真实验证。
- [HTTP 代理可能改变流式、升级或大响应语义] → 第一版明确支持范围和预算，不宣称兼容 WebSocket、任意上传或所有 HTTP 特性。
- [节点时间漂移影响过期] → 持久化绝对时间与单调运行时截止时间；恢复时选择更保守的过期判断。
- [目标服务在授权后发生变化] → 执行前重新读取实时证据并校验计划版本与服务指纹。
- [预授权范围过宽导致意外自动执行] → 默认无预授权；必须同时约束 peer、工具、资源、端口、持续时间和有效期。
- [进程崩溃留下入口] → 独立租约恢复器、资源所有权指纹和干净环境故障注入验收；不能证明所有权时宁可报告残留也不误删。
- [同一人拥有多节点但身份尚未被 Coordinator 统一管理] → 本 change 只依赖显式固定 peer 与目标节点本地策略，不根据模型或显示名称推断所有权。

## Migration Plan

1. 先引入操作模型、策略决策和假适配器，保持所有生产写能力关闭。
2. 使用假节点完成批准、预授权、拒绝、幂等、验证失败、回滚和恢复测试。
3. 完成 HTTP 临时代理技术验证，并固定平台适配器和资源所有权格式。
4. 在隔离端口上启用 macOS B 的首个临时入口，由 Windows A 验证；确认现有 WireGuard、Docker 和服务状态不变。
5. 在本地页面开放批准入口，默认仍无任何预授权。
6. 完成过期、崩溃恢复、卸载清理和失败注入后，才允许用户创建 L2 预授权。

回滚时关闭新写工具注册，停止创建新入口，并由恢复器仅清理所有权可验证的 TunnelMinion 临时资源；操作与审计记录保留用于诊断。

## Open Questions

- Python 内嵌代理和受管外部代理哪一种能在 Windows/macOS 上提供更可靠的连接排空、打包和异常清理，需要技术原型验证。
- 第一版是否支持 HTTPS 上游自签名证书，以及证书失败应如何向用户解释，需要真实家庭服务样本确认。
- HTTP 临时令牌采用单次使用还是租约内多次使用，需要在浏览器资源加载和安全性之间验证；当前倾向租约内有效、可主动撤销的短期令牌。
