## Why

TunnelMinion 已能基于本机与远端只读证据诊断“服务为何无法访问”，但仍只能给出建议，无法安全地完成修复闭环。下一阶段需要在不扩大为任意系统控制的前提下，让节点所有者能够批准或细粒度预授权一个低风险、可撤销、会自动过期的临时服务共享操作，并由请求节点验证真实结果。

## What Changes

- 将“临时发布服务”统一定义为“临时共享本机服务”：为原本只在目标节点本机可访问的 HTTP/HTTPS 或受支持 TCP 服务创建受控、限时、限来源的私网访问入口，不公开到互联网，也不修改服务本身。
- 引入 L0～L4 操作等级：只读观察、无副作用建议、低风险可逆操作、敏感操作和禁止操作。
- 由目标节点所有者配置权限策略；默认所有写操作需要明确批准，但允许对特定请求节点、工具、服务、时限和影响范围建立可撤销的 L2 预授权。
- 建立 Plan → Authorize → Execute → Verify → Rollback/Expire 工作流，使用幂等键、操作所有权、过期时间和稳定审计 ID 控制副作用。
- 第一版仅支持固定 A/B peer 间的临时服务共享；从请求节点验证可达性，验证失败时撤销本次创建的资源。
- 在本地 Web 页面展示计划、风险、授权依据、执行、验证、撤销和过期状态。
- 记录结构化操作结果，为后续“经验证的操作 Playbook”保留数据边界，但本次不实现跨节点经验检索、自进化或多 Agent。
- 本次不实现任意 Shell/Python、服务重启、Docker 控制、用户 WireGuard 配置修改、公共互联网暴露、Coordinator、多人企业权限或通用 TCP 转发。

## Capabilities

### New Capabilities

- `operation-policy`: L0～L4 操作等级、节点所有者权限、显式批准、细粒度预授权、撤销与拒绝规则。
- `temporary-service-sharing`: 对已识别本机服务创建限时、限来源、可验证且只删除自有资源的临时私网共享入口。
- `approved-operation-workflow`: 结构化计划、授权、幂等执行、请求节点验证、失败回滚、到期清理、恢复与审计状态。

### Modified Capabilities

无。

## Impact

- Agent Runtime 将新增结构化操作计划和审批工作流，但模型仍不能直接执行工具或提高权限。
- Tool Runtime 与 Gateway 将新增低风险写工具边界、授权决策、幂等键、操作所有权、过期与跨节点关联审计。
- Windows/macOS 平台层将新增隔离的临时共享适配器；只允许管理 TunnelMinion 创建并记录所有权的资源。
- SQLite 状态将新增操作计划、授权、执行、验证、清理和恢复记录。
- 本地聊天与资源页面将新增审批和操作生命周期视图。
- A/B 真机验收将增加成功共享、拒绝、重复请求、验证失败、节点离线、进程重启、过期清理和不破坏现有网络配置的场景。
