## Context

TunnelMinion 已有 `ContextBuilder`、对话持久化、长期记忆接口、工具运行记录和大结果制品化等基础，但这些部件没有统一约束全部生产模型调用。当前不同 Agent 路径可能只携带当前问题，也可能各自拼接工具结果，因此“模型看到了什么、为什么没看到某条信息、使用了哪个 prompt”难以复现。

本 change 横跨 Agent Runtime、模型 Provider、thread/checkpoint、memory、artifact、tool registry、运行追踪和评估。它只改善模型调用前后的上下文与 prompt 生命周期，不扩大工具权限，不改变确定性工具和有副作用操作的授权边界。

## Goals / Non-Goals

**Goals:**

- 所有生产模型调用通过同一个上下文组装入口，并生成不可变、可追踪的上下文快照。
- 在预算内组合当前意图、近期历史、滚动摘要、动态工具 schema、工具结果、制品引用和相关已确认记忆。
- 明确事实新鲜度与优先级，防止陈旧历史、错误记忆或不可信文本覆盖实时工具证据。
- 为 prompt 建立最小注册、版本、输入契约和运行关联，而不引入重量级 prompt 平台。
- 让上下文组成、裁剪和失败来源可观测、可测试、可回归。
- 模型或上下文失败时保持非 AI 的确定性能力可用。

**Non-Goals:**

- 不实现自动 prompt 搜索、在线自优化或模型自主修改 prompt。
- 不实现向量数据库、通用 RAG、跨节点经验自动共享或自动获得执行权限。
- 不实现多 Agent 辩论、角色编排或通用 Agent/Harness 平台。
- 不新增任意 Shell、代码执行、服务重启、网络修改或其他写权限。
- 不实现企业多租户、公共 SaaS、组织 RBAC 或集中式 prompt 管理服务。

## Decisions

### 1. 所有生产模型调用只接受 `ContextSnapshot`

Agent 路径不再直接构造 provider 消息，而是向 `ContextBuilder` 提交结构化 `ContextRequest`。Builder 返回不可变的 `ContextSnapshot`，至少关联 thread/run、任务类型、prompt 版本、工具 schema 版本、事实证据、记忆引用、制品引用、预算、裁剪决定和生成时间。Provider 只接受经过校验的快照。

选择统一快照而不是允许各 Agent 自行拼消息，是为了建立同一套安全、预算和追踪边界。测试与离线脚本可以使用同一接口构造固定快照；非生产假模型可保留专用测试入口，但不得被生产配置选择。

### 2. 使用固定事实优先级和显式冲突，不让模型自行决定新鲜度

事实优先级固定为：

```text
最新实时工具证据
  > 仍适用且由用户确认的长期记忆
  > 当前 thread 的滚动摘要与近期历史
  > 模型推断
```

工具证据带来源、采集时间、新鲜度和 tool run ID。长期记忆带节点、用户、任务范围、确认状态、修订链和删除状态。冲突由确定性组装器标注；模型可以解释冲突，但不能把低优先级内容提升为已确认事实。

被否决的方案是用向量相似度或模型评分统一排序所有内容。相关性不能代表真实性与新鲜度，且会让安全行为依赖不可复现的模型判断。

### 3. 对话历史采用“近期原文 + 滚动摘要”，并为每类内容保留独立预算

继续 thread 时优先保留当前用户消息、必要系统约束、最近若干轮原文和未完成工作流状态；更早内容进入带版本与覆盖范围的滚动摘要。工具 schema、工具结果、记忆与历史分别设预算，任何一类不能耗尽全部上下文。裁剪顺序与原因写入快照指标。

摘要是导航信息，不是实时事实来源。摘要生成失败时保留可容纳的近期原文并标记降级，不阻断确定性工具与资源页面。

### 4. 长期记忆必须经过作用域、状态、相关性和确认四道过滤

记忆只在用户、节点、任务类型和安全命名空间均匹配，且仍有效、未删除、未被修订替代、已由用户确认时进入候选集合。相关性排序只在通过硬过滤后进行。模型收到记忆 ID、类型、确认时间和必要内容，不收到其他用户或节点的候选记忆。

删除与修订采用持久化 tombstone/版本关系；缓存和摘要必须能按记忆 ID 失效。被否决的方案是只从数据库删正文，因为已有快照、缓存或摘要仍可能残留旧内容。

### 5. 大结果保存为制品，模型只获得有界预览

超过单项预算的工具结果写入现有制品存储，快照只包含制品 ID、来源 tool run、类型、大小、内容摘要或安全预览、截断标记和读取权限。制品正文不会因模型提出要求而自动展开；后续读取仍经过工具权限、预算和脱敏检查。

### 6. prompt 使用代码库内的最小版本注册表

每个生产 prompt 定义 `prompt_id`、语义版本、任务类型、模板、允许输入字段和中文变更说明。运行记录只关联版本和经过脱敏的输入摘要，不保存模型密钥或完整敏感内容。prompt 变更必须更新版本和相应黄金/对抗评估。

暂不引入外部 prompt 管理平台，因为当前单用户、本地优先部署更需要可审查、可随代码发布和离线复现的契约。未来若引入远程分发，仍必须固定运行时实际内容的哈希与版本。

### 7. 观测记录组成与决定，不默认记录完整正文

每次模型调用记录各类消息、工具 schema、结果、制品、记忆的数量与大小，预算使用、裁剪/摘要原因、prompt/模型/tool schema/证据版本、延迟、token 和成本。正文只进入已有受控存储，普通日志仅保留 ID、大小、哈希和脱敏摘要。

评估失败使用四类主归因：`context`、`prompt_or_model`、`harness_or_tool`、`governance`。归因可以附带次级原因，但不能用“Agent 回答错了”作为唯一结论。

### 8. 降级路径不依赖模型恢复

ContextBuilder、摘要模型或主模型失败时，AI 对话明确报告不可用或有限模式，不自动重放模型请求。确定性工具 API、资源面板、已有操作的批准/拒绝/撤销/过期/恢复/清理继续运行。任何写操作仍由原有授权、幂等、验证和审计路径处理。

## Risks / Trade-offs

- [统一入口可能遗漏现有隐蔽模型调用] → 先建立调用点清单和禁止 provider 直调的架构测试，再逐条迁移。
- [滚动摘要丢失重要约束] → 安全约束与未完成工作流状态使用结构化固定区，不依赖摘要；增加长对话回归集。
- [错误记忆进入上下文] → 先做确定性作用域与状态过滤，再做相关性排序，并覆盖删除、修订和跨命名空间测试。
- [上下文追踪泄露敏感正文] → 默认只记录元数据、哈希和脱敏摘要，制品正文继续走既有访问控制。
- [多类独立预算降低模型可见信息] → 在离线和真实模型评估中比较任务完成率与成本，按任务类型调整配置而不是取消上限。
- [prompt 版本增加维护成本] → 注册表保持代码内最小实现，只对生产 prompt 强制版本和评估关联。

## Migration Plan

1. 盘点所有生产 provider 调用点，建立阻止新增直调的测试和上下文快照契约。
2. 先以兼容模式让现有 Agent 通过 Builder 生成等价上下文，比较回答、工具选择、延迟和成本。
3. 接入近期历史、滚动摘要、记忆过滤、制品引用和分项预算，每步独立增加回归测试与指标。
4. 引入 prompt 注册表并给现有 prompt 分配初始版本，固定黄金和对抗评估基线。
5. 开启强制模式：生产 provider 拒绝无有效快照与 prompt 版本的调用。
6. 使用 Windows A/macOS B 的真实诊断场景验证新鲜度、隔离、降级和安全边界，再合并发布。

回滚时关闭强制模式并回到已验证的兼容快照配置，不删除 thread、memory、artifact 或运行记录。若发现隔离或秘密泄露风险，立即禁用相关记忆/制品注入路径，保留确定性工具与资源页面。

## Open Questions

- 首版预算以现有字符估算为主，还是在 provider 可用时同时记录 tokenizer 的 token 估算，需要通过不同模型的偏差评估决定。
- 滚动摘要使用主模型、较小模型还是确定性抽取，需要比较离线可复现性、成本和约束保真度。
- prompt 语义版本是否需要与应用版本独立发布，待首轮真实评估观察变更频率后决定。
