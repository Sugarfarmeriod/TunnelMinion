## Context

当前后台观察任务若过早确定基线，Uvicorn 的本机面板端口或首轮系统采集中出现的短命端口会在后续确认窗口被识别为服务变化。Windows 正式包重复验证稳定复现首张快照里的随机高位 UDP 端口在第二张消失并形成 `service_removed`，与 Windows/macOS 首次启动不得产生启动 incident 的既有规格不符。

调查循环首轮设置了 `require_tool_call=true`，但 OpenAI-compatible 后端可能返回结构有效、没有工具调用的 `insufficient_evidence`。当前 Runtime 只在该响应结构无效时执行本机只读兜底。2026-09-05 的 macOS 正式包重复验证得到 0/3 工具命中和 0/3 证据化结论，证明合法无工具响应在本机服务场景中虽然安全，却没有用户价值。

## Goals / Non-Goals

**Goals:**

- Windows 与 macOS 全新数据目录首次启动时，以前两次完整观察作为稳定期并用第二次结果建立基线，不创建启动 incident 或调用模型。
- 监听工具排除可识别的 UDP 客户端连接，同时保留未连接 UDP 端点和全部 TCP 监听。
- 本机观察产生的 `service_added` 首轮只暴露监听工具；第一次模型响应未选择工具时，通过现有 Tool Runtime 获取一次监听证据，再允许模型结束调查。
- 工具失败、模型失败和证据不足继续形成保守终态；所有现有预算、审计、参数校验和证据门槛保持有效。
- 远端、Coordinator 目录和聚合来源绝不暴露或执行当前节点的本机工具。

**Non-Goals:**

- 不改变模型 Provider、模型服务或提示词，不增加重试层和新依赖。
- 不增加工具，不执行 Shell、Python 或任何网络与系统写操作。
- 不处理 packet relay、复杂 Provider、自动组网、showcase、WireGuard、防火墙、路由或 DNS。

## Decisions

1. **全新数据目录用前两次完整观察完成启动稳定期。** 后台循环仍在首个周期结束后拍第一张快照，但不比较前两张结果，并以第二张作为正式基线；已有持久化快照的重启则立即沿用该基线。相比按 PID、协议或端口排除对象，这不需要隐藏真实服务，也能吸收应用面板和短命 UDP 端口的启动抖动。代价是全新安装前两个观察周期内的变化会进入初始基线；这与“先稳定、再监测”的启动语义一致。

2. **只对 `local_observation` 来源的服务对象执行首轮确定性取证。** `service_added` 首轮只暴露 `list_network_listeners`，避免模型拿节点摘要等场景无关结果提前收敛；当 `tool_calls == 0` 且尚未执行工具时，Runtime 使用同一定义构造一次兜底调用。无论首轮无工具响应的结构有效与否，都先取得实时监听证据；节点对象继续沿用现有“仅无效结构才兜底”的行为。

3. **一次监听尝试后恢复现有模型循环。** 工具结果仍经过 schema、平台策略、超时、结果大小和审计边界；取得工具证据后的请求携带既有调查决定 JSON Schema，无本机工具的远端来源则从首轮携带该 Schema。`service_added` 后续只保留 `list_network_listeners` 与 `get_process_summary`，模型可补充进程证据、基于已有证据形成结论或安全结束。Runtime 不伪造结论，也不把工具成功等同于根因确认。

4. **保留远端证据隔离。** 非 `local_observation` 来源不得向模型暴露或运行当前节点的本机工具；模型即使主动请求，也不能把本机结果记到远端对象。结构有效的证据不足报告可保留；结构无效或请求未暴露工具则按现有失败路径结束。

5. **真实验收使用正式 CI 包和隔离监听。** Windows/macOS 各运行 5 个全新数据目录样本，只创建非特权临时监听并通过 SQLite 只读观察结果。总计至少 8/10 取得 `list_network_listeners` 成功证据、至少 7/10 形成引用工具证据的结论，且无无证据确认、禁止工具执行或场景无关工具调用。

6. **监听器只保留 UDP 本地端点。** psutil 结果中带 `raddr` 的 UDP socket，以及 macOS `lsof` 端点中带 `->` 的 UDP 记录，代表已连接客户端而不是监听服务，必须在平台读取边界丢弃。没有远端地址的 UDP 端点继续保留，因此不按端口范围或进程名猜测，也不会隐藏 WireGuard 等真实 UDP 服务。

## Risks / Trade-offs

- [全新安装前两个观察周期内的服务变化会被视为初始基线] → 明确把该窗口定义为启动稳定期；已有持久化基线的重启不重复等待，基线建立后的变化仍使用两次确认规则。
- [确定性监听调用仍可能失败或返回部分结果] → 复用现有 Tool Runtime 状态与证据规则，失败时保持 `insufficient_evidence`，不补写推测。
- [模型服务偶发不可用会降低实机通过率] → 门槛允许少量失败，但不在本阶段增加重试或改动模型服务；超出容忍度时保留失败证据。
- [本机服务首轮比以前多一次工具调用] → 仅在模型违背首轮工具要求时触发，且固定为与服务事件直接相关的只读监听工具。
- [部分平台无法报告 UDP 远端地址] → 只在系统事实明确给出远端地址时排除；无法区分的 UDP 端点继续保留，不做启发式猜测。

## Migration Plan

无数据迁移或 API 迁移。发布新包后观察调度和调查行为自动生效；回滚只需恢复上一正式包，现有 SQLite 数据仍兼容。
