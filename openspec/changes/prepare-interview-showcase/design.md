## Context

TunnelMinion 的工程能力已经覆盖本地产品壳、跨节点诊断、候选操作、目标节点授权、执行后验证和恢复证据，但这些能力分布在多个活动 change 与 Draft PR 中。面试展示必须在不改变产品安全语义、不抢占现有 change 所有权、不把 Draft 或 fixture 冒充已发布能力的前提下，将它们组织为一条可在三分钟内理解的真实闭环。

当前 `complete-managed-path-runtime` 和 `improve-local-product-experience` 仍有独立门禁；前者的真实阶段 6–7 需要用户另行授权资源，后者仍需稳定的后端契约、真实 A/B 和最终发布门禁。本 change 因此先建立展示契约和证据纪律，待依赖进入明确稳定基线后再实现公共 README、UI、截图和录屏。

## Goals / Non-Goals

**Goals:**

- 用 30 秒定位、三分钟主流程和按需技术深挖讲清 A/B 安全闭环。
- 复用 `Thread`、`Run`、`Operation`、`Evidence`，让产品画面而非架构课件承担主演示。
- 为 README、现场演示、录屏、离线 SVG、截图和评估结果建立一致的信息结构与来源追踪。
- 区分 `main` 已交付、Draft PR 已验证、计划中和禁止宣称，阻止历史或降级证据被错误外推。
- 在模型、节点或现场环境异常时，仍能用录屏和可审计证据诚实完成演示。

**Non-Goals:**

- 不实现 A/B/C 三个独立 Agent 的直接通信、通用多 Agent 编排或 `Mission` 领域对象。
- 不实现邀请入网、n2n/relay、模型 fallback、额度路由或新的网络 Provider。
- 不执行 `complete-managed-path-runtime` 的真实阶段 6–7，也不把现有 WireGuard、路由、防火墙、模型、秘密或自启动纳入展示写入目标。
- 不修改 PR #40/#59 的 OpenSpec artifacts、公共任务状态或未稳定实现。
- 不为了演示生成假成功、预写漂亮指标或展示隐藏推理、秘密和未脱敏原始工具数据。

## Decisions

### 1. 首版采用 A/B 安全闭环

主演示固定为“查看设备/服务与访问地址 → Agent 只读诊断 → 无权限候选处理 → 必要的目标节点本地批准 → 执行与独立验证 → 恢复/清理证据”。默认场景使用中性的本地 PDF 服务，不以游戏或三 Agent 数量作为卖点。

被否决的替代方案：把 A/B/C Agent 直接互动作为首版硬门槛。该方案需要新的通信、并发、幂等和冲突协调能力，应由未来独立 change 负责，不能伪装成展示包装。

### 2. 复用现有领域，不新增展示专用后端模型

展示信息按照 `Thread → Run → Operation → Evidence` 组织：`Thread` 保存用户问题，`Run` 展示公开工具轨迹，`Operation` 展示候选处理与授权状态，`Evidence` 展示验证、恢复和清理结果。最小信息聚合仅在依赖稳定后评估，不新增 `Mission` 或展示专用权威状态。

被否决的替代方案：用新的 `Mission` 统领所有页面。它会把展示工作扩大为后端领域重写，并与现有 LPE 和 Agent 工作流重复。

### 3. 所有展示声明都必须绑定证据状态

建立 claim-to-evidence manifest，每条声明至少记录：状态分类、来源提交、分支或 PR、环境、平台、验证命令或报告、采集时间、适用范围和脱敏资产。状态分类固定为：

- `main-verified`：已进入当前稳定主线并在相应环境复核；
- `draft-pr-verified`：只在明确 Draft PR head 上验证；
- `planned`：仅为规划，不得进入成果数字或成功画面；
- `prohibited-claim`：缺少授权、真实资源或稳定基线，禁止对外声称完成。

最终发布素材只能使用本轮稳定基线重新采集的证据。历史 A/B、fixture、降级成功或旧 PR head 只能作为标明来源的背景材料。

### 4. 规划和实现分两阶段推进

规划与前置工作包阶段唯一主写者只修改 `openspec/changes/prepare-interview-showcase/**` 和仓库内非公开、非最终的 `docs/interview-showcase/**` 工作包，可以完成依赖矩阵、证据 schema、信息架构、逐秒脚本、README 大纲、素材清单、离线 fixture 设计和评估矩阵。不得修改根 README、`frontend/`、最终截图或录屏、外部图纸或其他 change。

实现阶段必须从届时最新且已同步的稳定基线开始，并在写公共文件前重新核对 PR #40/#59 的合并状态、任务所有权和真实证据门禁。若依赖仍是 Draft，只能保留规划，不进入最终素材制作。

### 5. 现场演示必须有诚实的降级路径

现场演示优先运行真实产品流程；录屏负责稳定重现同一提交上的完整闭环；离线 SVG、截图、脱敏 manifest 和验证报告负责技术深挖与故障兜底。模型不可用时只能展示确定性资源与已有操作控制，不能播放录屏并冒充当前现场成功。

离线 fixture 覆盖超时、节点离线、重复或乱序事件、矛盾证据、模型故障和操作失败，但所有 fixture 必须有明显标记，不得进入真实 A/B 指标。

### 6. 图纸和发布证据保持分层

自部署 Penpot 是当前可编辑图源，仓库内离线 SVG、Mermaid 源和脱敏 manifest 是可审计发布证据。规划阶段不写外部图纸；最终实现仅在用户另行授权、归属明确且单一写入者成立时更新 Penpot。主演示默认不以架构图开场，生命周期图用于流程收束，安全架构和审批图用于回答深入问题。

## Risks / Trade-offs

- [依赖 PR 长期未稳定导致展示实现停滞] → 先完成独立规划与证据台账，公共 UI、README 和录屏保持门禁关闭。
- [展示包装掩盖未完成能力] → 每条声明强制分类并绑定 SHA、环境和采集时间；`planned` 不进入成果数字。
- [现场模型或网络不稳定] → 使用同一稳定提交的录屏和离线证据兜底，并明确说明当前降级状态。
- [为了故事完整而扩大产品范围] → 首版固定 A/B 安全闭环，三 Agent、邀请入网和模型路由分别进入未来 change。
- [与 PR #40/#59 同文件写入] → 规划与前置工作包阶段只写本 change 和 `docs/interview-showcase/**`；公共实现等待 owner 和合并顺序重新确认。
- [历史图纸或截图与当前代码不一致] → 最终素材在稳定基线上重采集，并通过 manifest 对齐图源、导出物和提交。

## Migration Plan

1. 在独立规划分支完成并审阅本 change；前置工作包仅写 `docs/interview-showcase/**`，不修改产品代码和公共展示文件。
2. 等待 PR #59/#40 及必要真实门禁形成明确稳定基线；未满足时保持规划状态。
3. 从最新稳定 `main` 创建后续实现分支，先生成 evidence manifest，再实现 README、演示材料和必要的最小信息聚合。
4. 在 Windows/macOS 与获准的 A/B 环境重新采集证据，完成独立审计后发布素材。
5. 若实现或素材产生误导，回滚展示分支和发布资产，不影响 Agent、网络、授权或现有产品运行时。
