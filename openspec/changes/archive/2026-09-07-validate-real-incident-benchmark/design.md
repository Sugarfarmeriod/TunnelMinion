## Context

`autonomous-incidents-v2.json` 已覆盖固定故障矩阵，`run_incident_dataset` 也确实经过 detector、`IncidentInvestigator`、`ToolRuntime` 和 SQLite；但 `_FixtureProvider` 直接读取每个场景的 `tool_sequence` 与期望结论，因此当前满分是脚本化回归结果。下一步必须在不接触真实系统状态的前提下，让真实模型面对同一生产调查循环并自行选择工具。

本阶段的使用者是产品开发者和评审者：前者需要知道是否值得进入“事故转审批操作”阶段，后者需要逐场景复核模型调用、实际工具轨迹、证据和停止原因。模型服务由用户在仓库外维护，本阶段只能发起隔离请求，不能读取密钥、启动、停止或切换服务。

## Goals / Non-Goals

**Goals:**

- 让真实 OpenAI-compatible 模型驱动现有 `IncidentInvestigator`，且评分答案不进入模型上下文。
- 使用版本化、场景相关的确定性只读工具结果，保存模型实际请求与 Runtime 实际执行的差异。
- 报告六项核心指标、逐轮元数据、token（若 Provider 返回）、延迟、代码版本和安全硬门槛。
- 覆盖证据冲突，并以一次串行完整矩阵生成可复核证据。

**Non-Goals:**

- 不新增模型 Provider、密钥管理、自动重试或模型服务生命周期管理。
- 不调用真实系统工具，不修改正式产品、UI、网络、审批操作或长期记忆。
- 不用单次随机波动驱动 Prompt 调参；只有可重复的产品缺陷才进入后续 change。

## Decisions

1. **在现有 incident 数据集模型上增加评分真值和工具夹具。** 新的 v3 数据集为每个工具保存场景相关 JSON 结果，并为根因评分保存不向模型公开的关键词；`tool_sequence` 只供原有脚本化回归使用。真实模式只把 incident 快照、生产 Prompt、工具 schema 和模型主动请求后的工具结果交给 Provider。另建一套相似数据模型会产生两份漂移的矩阵，因此不采用。

2. **复用生产调查链，只替换边界依赖。** detector、`IncidentInvestigator`、上下文构建、`ToolRuntime`、预算和 SQLite 均使用现有实现；工具适配器只返回 v3 场景夹具，绝不读取本机或远端实时状态。直接手写模型消息循环会绕过本阶段要证明的生产行为，因此不采用。

3. **用轻量 Provider 记录器观察真实选择。** 记录器包住现有 Provider，只保存每轮响应类型、工具名、错误码和 token 计数，不保存隐藏思维链或未经脱敏的原始正文。工具选择指标使用模型实际请求；审计轨迹使用 Runtime 实际执行；两者的差异明确标记为受控 Runtime fallback，避免把兜底调用冒充模型能力。

4. **同一运行器支持脚本化与真实两种 scope。** 未注入 Provider 时保持现有快速回归；注入 Provider 时，除 `model_failure` 使用确定性故障注入外，其余触发场景均调用真实模型。正常刷新仍必须零模型调用。这样保留稳定 CI，也不会把真实模型可用性变成每次提交的外部依赖。

5. **安全门槛与质量目标分开。** 禁止工具执行、无证据确认结论、正常刷新调用模型是零容忍硬失败；根因成功率、工具选择率、非必要调用率、失败恢复率和延迟作为真实质量数据，并用明确目标标记是否适合进入下一阶段，但一次诚实的未达标结果仍是有效评测证据。首轮就要求所有随机指标 100% 会诱导针对样本调参，因此不采用。

6. **真实矩阵串行且只跑一次完整基线。** 本机模型显存有限，串行执行避免并发放大内存峰值。运行器只连接给定 endpoint；连接失败或显存不足时如实退出，不重启、卸载或切换现有服务。DeepSeek 可在未来用同一 OpenAI-compatible 入口复测，不在本阶段增加专用代码。

## Risks / Trade-offs

- [模型输出具有随机性] → 固定数据集、Prompt、工具版本、代码提交和 Provider 元数据；首轮只作基线，只有重复失败才形成修复需求。
- [关键词评分漏掉语义等价答案] → 使用少量领域关键词并同时保留结论、证据和人工可审计轨迹；不引入第二个模型裁判。
- [确定性夹具不等于真实 A/B 环境] → 报告 scope 明确标为隔离真实模型评测，既有 A/B 真机证据继续单独保存，不互相冒充。
- [本地模型再次内存不足] → 串行和有界轮次降低峰值；失败时保留明确错误，不控制 8080 进程。
- [评分字段意外泄露给模型] → 单元测试捕获实际 `ModelRequest`，验证评分字段名和脚本序列未进入消息；真实报告分别列出模型请求与 Runtime 执行。

## Migration Plan

保留 v2 数据集和现有脚本化入口供正式产品夹具与 CI 使用；新增 v3 数据集和真实 incident CLI。先提交实现与离线测试，再以该提交号运行真实模型矩阵并单独提交证据。若真实入口有问题，删除新增入口和 v3 即可，正式产品无需迁移或回滚。
