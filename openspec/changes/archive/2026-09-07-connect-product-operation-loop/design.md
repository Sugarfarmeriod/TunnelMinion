## Context

临时共享底座已经存在：`CrossNodeDiagnosticAgent` 与 `CandidateOperationPlanner` 能产生无权限 L2 计划，`FixedGatewayClient` 能提交和执行，目标节点状态机能批准、验证、回滚和到期清理，React 操作页能展示目标节点记录。当前断点是这些生产组件没有请求端调用者；完整链路只能由 `scripts/run_safe_sharing_ab_acceptance.py` 临时组装，浏览器也没有安全取得共享内容的产品路径。

本阶段只连接既有路径。实际写操作仍发生在目标节点的既有 `HTTPSharingAdapter` 中，并继续要求目标节点策略授权。实现与自动验收不得修改 WireGuard、防火墙、路由、Docker、服务或生产端口。

## Goals / Non-Goals

**Goals:**

- 用户在请求节点的 React 操作页选择已配置 peer、目标服务端口、共享端口和时长，明确确认后完成最新只读诊断、候选计划和目标节点提交。
- 请求节点保存不含秘密的操作请求与最近远端摘要，页面刷新或进程重启后仍能按同一 `operation_id` 查询，不自动重放未知写请求。
- 目标节点授权后，请求节点启动一次有界验证回调、幂等请求执行，并只在请求节点真实验证通过后提供同源环回访问入口。
- 临时访问凭据仅存在于请求节点进程内存；目标节点仍负责租约、资源所有权、回滚和到期清理。

**Non-Goals:**

- 不改变模型 Provider 或恢复 DeepSeek 配置，不新增 relay、自动组网、复杂 Provider、通用 TCP、HTTPS/WebSocket、服务重启、Docker 控制或网络配置能力。
- 不自动批准、自动重试提交/执行、在重启后重建临时凭据，或让请求节点撤销目标节点所有者的授权决定。
- 本阶段自动验收只使用 fake/ASGI transport 与隔离回环端口；真实 A/B 网络操作留待用户另行明确授权。

## Decisions

### 1. 新增一个请求端编排服务，复用既有领域组件

新增最小 `RequesterOperationService`，负责解析已配置 peer、调用既有跨节点诊断与候选计划器、持久化本地请求记录、调用 `FixedGatewayClient`、管理一次性验证回调和内存访问会话。模型仍只生成说明字段，不接触 Gateway token、callback token、访问凭据或写适配器。

被否决的方案：把验收脚本作为产品子进程调用。脚本以文件在两个命令间传递计划，缺少产品级恢复、同源请求保护和状态展示。

### 2. 请求端记录与目标端权威操作分库存放

在现有 SQLite 增加请求端记录表，保存完整计划、最近一次脱敏 `RemoteOperationResult.summary`、提交/执行结果是否未知、最后查询时间和稳定错误码。它不保存访问凭据，也不伪造目标节点的授权、资源、验证或状态迁移详情。目标节点的现有 `operations` 表继续是执行生命周期权威来源。

操作 API 合并两类记录并显式返回本机角色 `requester` 或 `target`。目标角色保留批准、拒绝、取消和撤销；请求角色只允许查询远端状态、在远端已授权时执行，以及在内存会话存在时访问。

被否决的方案：把远端摘要强行转换成目标端 `OperationRecord`。摘要缺少完整授权和验证子记录，伪造状态历史会制造错误证据。

### 3. 浏览器只能提交节点 ID 和有限计划参数

服务端从 `gateway.json` 选择已配置且允许 `share_local_http_service` 的 peer，使用密钥存储中的现有凭据建立固定客户端；远端 endpoint、目标绑定地址和本机验证地址均由该配置推导。浏览器只提交目标节点 ID、服务端口、共享端口、持续时间和明确确认位，不能提交 URL、Gateway token、callback token、访问凭据或工具证据。

模型不可用、peer 未配置、凭据缺失或最新诊断不满足环回 HTTP 条件时，只拒绝新请求；已有目标端操作控制和请求端只读状态仍可使用。

### 4. 远端写请求前先持久化，未知结果只查询

候选计划生成成功后，请求端先保存计划，再调用目标节点提交。提交或执行响应超时/中断时，记录 `result_unknown`，页面只允许按原 `operation_id` 查询；系统不得自动重新提交、重新执行或生成新计划。明确的目标端 4xx 作为已裁决失败展示。

### 5. 执行时临时开放受控验证回调

请求端在调用远端执行前，把一次性回调只绑定到本机已配置的 WireGuard 地址和可配置端口。回调 token 使用高熵随机值，只在当前执行内存中存在；端口无法绑定时在远端执行前失败。目标节点通过现有 `CallbackRequesterVerifier` 把本次访问凭据交给请求端验证器，请求端沿计划地址执行既有有界健康检查。

默认回调端口沿用已验证的 `18900`，并作为非秘密 Gateway 配置项保留调整能力；实现不打开防火墙，也不探测或改写网络规则。

### 6. 成功后使用本机同源代理，不把凭据交给浏览器

验证器仅在验证通过时把访问凭据和租约保存到进程内有界会话表。React 打开的 `/api/operations/{id}/access/{path}` 由本机服务端以固定计划地址代理 GET/HEAD，请求预算复用现有 HTTP 共享限制；URL、响应错误、浏览器存储和普通日志均不包含凭据。

进程重启、租约过期、远端状态不再成功或内存会话不存在时，访问入口立即不可用，不尝试恢复凭据或重放执行。目标节点的绝对租约仍负责最终清理。

### 7. 扩展现有操作页而不新建产品外壳

React 操作列表增加“请求临时访问”表单，数据来自服务端返回的合格 peer 列表。详情页按本机角色显示目标端控制或请求端查询/执行/访问动作；所有写动作提交前复读最新状态，结果未知时沿用现有“只查询、不重放”交互。

## Risks / Trade-offs

- [请求节点回调端口未被现有网络策略允许] → 绑定失败或远端回调失败时保守回滚并展示稳定错误；TunnelMinion 不修改防火墙。
- [请求端进程重启后丢失访问凭据] → 明确显示访问会话已失效，继续查询目标状态并等待目标租约清理，不恢复或持久化秘密。
- [请求端缓存摘要落后于目标状态] → 标注最后查询时间，执行前强制读取目标节点，列表缓存不得冒充实时事实。
- [代理不能兼容复杂 Web 应用] → 本阶段只保证有界 GET/HEAD 与相对资源路径；HTTPS、WebSocket、上传和通用 TCP 保持非目标。
- [同一操作在两端状态文字不同] → 目标端记录保持权威，请求端只保存脱敏远端摘要和本地结果确定性，不合成远端缺失证据。

## Migration Plan

1. 增加向后兼容的请求端 SQLite 表及 Gateway 回调端口默认值；旧配置无需迁移即可读取。
2. 先以 fake 客户端和 ASGI transport 验证提交、授权等待、执行、回调、访问、未知结果与重启降级。
3. 接入 Windows/macOS 本机应用和 React 页面，保持既有目标端操作 API 与 legacy 页面可用。
4. 通过完整门禁和独立审计后合并；若需回滚，关闭请求端入口即可，目标端已有操作仍按租约清理。

## Open Questions

无阻断性设计问题。真实 A/B 回调端口可达性和产品包跨机体验必须在用户明确允许网络操作后单独验收，不能由本阶段隔离测试冒充。
