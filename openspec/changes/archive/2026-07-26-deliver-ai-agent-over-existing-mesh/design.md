## Context

TunnelMinion 当前没有实现代码，但已具备真实测试条件：Windows 节点 A 与 macOS 节点 B 通过现有 WireGuard 隧道互通，B 同时是 WireGuard 服务器与普通节点。用户希望构建的不是传统 VPN 客户端或附带聊天框的服务面板，而是一个分布在组网节点上的 AI Agent 系统。

每个节点 Agent 需要具备模型推理、工具调用、上下文、长期记忆和自主诊断能力，同时能够通过远端节点提供的受控工具理解跨设备状态。系统必须避免把实时状态误当记忆、把所有工具一次性暴露给模型，或让模型直接生成代码操作系统。

MVP 只复用现有 A/B 网络并提供只读能力。这样可以先验证最核心且最有差异化的假设：模型能否根据真实跨节点工具证据，可靠回答“远端有什么服务”和“为什么无法访问”，而不先承担自动组网、三端打包与写操作安全的全部复杂度。

## Goals / Non-Goals

**Goals:**

- 在 A、B 上运行结构一致的 Python AI Agent Runtime 与本地聊天/资源面板。
- 让用户配置自己的模型 API，并由 Agent 完成有预算、有停止条件的工具调用循环。
- 用确定性工具读取 WireGuard、端口、进程、Docker 和服务可达性。
- 通过现有 WireGuard 网络安全调用远端节点的只读工具。
- 明确分离实时状态、短期上下文、工作流 checkpoint 与长期记忆。
- 对工具选择、参数、任务结果、证据、安全、延迟与成本进行可重复评估。
- 保护现有 `HomeMac` 和 B 的手写 WireGuard 配置，确保 MVP 没有网络写路径。

**Non-Goals:**

- 不自动创建、修改或删除 WireGuard 接口、peer、路由、密钥或配置文件。
- 不实现临时服务发布、容器启停、服务重启或其他有副作用工具。
- 不向模型提供任意 Shell、Python REPL、文件读写或运行时生成代码能力。
- 不实现 n2n、自动 NAT 穿透、回退中继或 Coordinator 完整控制面。
- 不实现多 Agent 辩论、角色扮演、子 Agent 群或通用 coding agent。
- 不扫描物理局域网，不读取容器环境变量、业务正文、用户文件或 WireGuard 私钥。
- 不要求 Linux、安装包、自动更新或完整游戏识别进入首个 MVP。

## Decisions

### 1. AI Agent 与 Node Runtime 作为同一产品的不同边界

每个节点运行一个 Python 3.11+ Node Runtime，内部包含：

- `agent`：模型 Provider、工具调用循环、上下文组装和回答生成。
- `tools`：结构化工具注册表、权限、参数校验、执行与审计。
- `platform`：Windows/macOS 的 WireGuard、端口、进程和 Docker 只读适配。
- `memory`：会话 checkpoint、摘要、长期事实和用户偏好。
- `gateway`：通过 WireGuard 地址提供经过认证的远端只读工具入口。
- `web`：仅监听环回地址的聊天和资源面板。

LangChain 用于首个工具调用 Agent；LangGraph 用于 checkpoint/persistence，并为后续需要暂停审批的写操作工作流保留边界。MVP 不为了展示框架而把所有确定性流程建成图。

被否决的方案：只实现传统 Node Agent，再把模型作为服务名称增强器。该方案无法体现用户要求的自主工具调用、上下文记忆和跨节点诊断价值。

### 2. 每个节点独立配置模型 Provider

模型配置至少包括 Provider 类型或兼容协议、API endpoint、model identifier、API key、超时和可选预算。API key 只保存于所属节点的受保护存储，不通过远端工具、日志、记忆或 Coordinator 同步。

配置保存前执行最小连通验证；失败不阻止 Node Runtime 和资源面板启动。模型不可用时，本地工具和资源视图继续工作，聊天明确显示降级状态。

MVP 优先支持一种经过验证的兼容接口，但模型访问层保持 Provider 边界。未经原型验证，不承诺任意供应商都能一致支持工具调用和结构化输出。

被否决的方案：把所有节点模型调用集中到 B。该方案会集中 API key、用户对话和工具结果，违背本地优先并制造单点故障。

### 3. 工具是预定义、结构化和有风险等级的 Python 能力

每个工具元数据包含稳定名称、版本、说明、输入 schema、输出 schema、风险等级、平台、权限要求、超时、最大结果大小和数据敏感级别。MVP 只注册 `read-only` 工具：

- `get_wireguard_status`
- `list_network_listeners`
- `get_process_summary`
- `list_docker_services`
- `probe_service_reachability`
- `get_node_summary`

所有模型参数先通过 schema 校验；执行发生在受控函数中而不是命令字符串中。底层适配器可以调用受允许的系统 API 或固定命令，但模型看不到命令模板，也不能注入额外参数。工具设置超时、并发和输出预算，并为每次调用生成 `tool_run_id`。

工具结果使用结构化对象返回；日志、HTTP 标题、容器标签等外部文本标记为不可信数据并进行长度限制。模型最终回答必须能引用工具、目标节点、时间和 `tool_run_id` 作为证据。

被否决的方案：给模型一个通用 Shell 或 Python 工具。它虽然演示效果强，但无法建立可靠权限、跨平台一致性和可测试边界。

### 4. 按任务和节点动态暴露工具

模型默认只看到少量本地元工具与当前任务需要的只读能力。跨节点诊断采用分阶段工具发现：先获取已配置节点及能力摘要，再由 Runtime 根据目标节点、授权和任务阶段将允许的远端工具加入下一次模型调用。

工具选择逻辑同时受确定性策略约束：MVP 禁止任何非只读风险等级；离线节点、未认证节点或平台不支持的工具不会进入模型工具集合。模型不能通过编造工具名称绕过注册表。

被否决的方案：把 A、B 以及未来所有节点的全部工具 schema 永久放入系统提示。该方案会扩大上下文、增加错误工具选择，并难以表达节点权限变化。

### 5. 远端工具网关只通过现有私有网络提供

A/B 首版使用显式 peer 配置记录节点名称、WireGuard 地址、网关端口和认证材料。远端网关只绑定受管 WireGuard 地址，不绑定公网、物理局域网通配地址或环回面板端口。

每个请求包含调用节点身份、会话/run ID、工具版本和超时。网关验证节点、工具允许列表、参数 schema、速率限制与结果预算，并返回来源节点及执行时间。MVP 只允许 A/B 之间调用只读工具。

跨节点协议在实现前比较 MCP remote transport 与小型版本化 HTTP/RPC 网关。选择标准是节点认证、工具能力发现、超时取消、流式结果、可观察性和 Python 维护成本；该选择是待验证假设，不把 MCP 名称本身作为目标。

被否决的方案：让浏览器直接访问远端 Agent。浏览器不应持有节点工具凭据，远端调用必须由本机 Runtime 代理和审计。

### 6. 上下文和记忆分为四类存储

- **实时状态**：每次通过工具获取；可短时缓存，但不写入对话长期记忆。
- **短期上下文**：当前线程消息、工具选择和必要结果摘要；使用 token 预算、窗口裁剪和滚动摘要。
- **工作流 checkpoint**：run 状态、调用次数、剩余预算、取消状态和错误；用于重启恢复或诊断。
- **长期记忆**：用户确认的节点别名、偏好、安全约束和稳定服务事实；按用户/节点 namespace 保存，可查询、修正和删除。

大型工具结果保存为本地 artifact，通过引用和摘要进入模型上下文，不把完整端口列表、日志或历史轨迹反复传给模型。长期记忆不得保存 API key、私钥、认证头或未经确认的模型推测。

MVP 使用本地持久化存储抽象；初始实现可采用 SQLite，但 checkpointer、artifact store 和 memory store 保持独立接口。

被否决的方案：把所有历史消息和工具原始结果当作 memory 无限制追加。该方案会造成上下文爆炸，并混淆旧状态与实时事实。

### 7. 只读诊断使用有界 ReAct，确定性任务不调用模型

用户提出开放式问题时，Agent 进入有界工具循环：理解目标、选择允许工具、读取结果、判断信息是否足够并回答。每个 run 设置最大模型轮次、最大工具调用数、墙钟超时、取消信号和可选成本预算。达到限制时，Agent 基于现有证据返回不完整结论并说明缺口。

定时端口枚举、Docker 读取、状态刷新和健康检查由普通 Python 调度执行，不经过模型。单个服务的确定性分类优先使用规则；只有需要自然语言解释时才调用模型。

Plan-Execute-Replan 不作为所有请求的默认模式。后续有副作用 change 使用显式 LangGraph：Plan → Policy Check → Human Confirm → Execute → Verify/Rollback。

### 8. 本地面板同时展示对话、工具轨迹和资源

Web UI 与本地 API 只监听 `127.0.0.1`/`::1`。聊天流展示当前阶段、目标节点、工具名称、成功/失败和耗时，但隐藏模型内部思维、秘密和过量原始数据。用户可以取消 run、查看证据详情、开始新线程并删除会话。

资源视图直接展示确定性工具快照，使模型不可用时仍可查看节点、WireGuard、端口和 Docker 状态。远端文本按不可信纯文本渲染。

### 9. 评估是 MVP 交付物而非附属脚本

测试分为三层：

1. 假模型与假工具的确定性单元/集成测试，覆盖工具选择、错误参数、超时、取消和上下文裁剪。
2. 固定场景评估集，包含期望工具、禁止工具、关键证据和可接受答案事实。
3. A/B 真机端到端评估，覆盖远端服务发现、环回监听诊断、节点离线、Docker 不可用和模型失败。

报告至少输出工具选择准确率、参数有效率、任务完成率、证据一致率、禁止工具调用数、平均模型轮次、工具次数、延迟和可获得的模型成本。评估记录模型、prompt、工具版本和数据集版本，便于回归比较。

## Risks / Trade-offs

- [模型编造工具或参数] → 动态注册表、schema 校验、枚举约束、错误反馈和评估集共同限制。
- [上下文随节点与服务数量增长] → 分阶段能力发现、任务级工具过滤、artifact 引用、滚动摘要和硬预算。
- [工具结果携带 prompt injection] → 结果标记为不可信数据、限制内容类型与长度，不允许外部文本改变系统策略。
- [远端网关扩大攻击面] → 只绑定 WireGuard 地址、节点认证、只读允许列表、速率限制、审计和最小数据返回。
- [模型给出无证据结论] → 回答必须关联工具证据；评估比较回答事实与固定工具结果。
- [真实 A/B 状态导致测试不稳定] → 核心回归使用假工具/录制 fixture，真机测试作为独立标记的验收层。
- [Python 跨平台系统查询差异] → 平台适配层与能力降级；权限不足时返回结构化 unsupported/permission 错误。
- [模型调用成本和延迟过高] → 限制轮次、工具预算、超时和结果规模，记录每场景成本并优先确定性处理。
- [MCP 选择后发现认证或兼容不足] → 在协议 spike 后用 ADR 决定；业务工具 schema 不依赖具体传输。
- [项目再次演变为常见聊天/RAG Demo] → MVP 验收必须在真实 A/B 上完成跨节点工具链路和证据化诊断。

## Migration Plan

这是新实现，没有历史数据迁移：

1. 建立假模型、工具注册表、状态/记忆接口和本地聊天纵向切片。
2. 在 A 上实现只读 Windows 工具与资源面板，确认不会写入 WireGuard。
3. 在 B 上实现 macOS 只读工具与网关，使用独立认证材料。
4. 先通过固定工具调用验证 A→B，再允许模型动态选择远端工具。
5. 加入上下文预算、持久化 checkpoint、长期记忆和删除能力。
6. 执行固定评估集和 A/B 真机验收，生成基线报告后发布 MVP。

卸载或回滚只停止 Runtime、删除 TunnelMinion 自己的模型配置、数据库与网关认证材料；不得修改现有 WireGuard 接口、服务、配置或密钥。长期记忆和评估结果在删除前允许用户导出。

## Open Questions

- 首个模型兼容接口和最低工具调用能力要求需要通过用户可用 API 实测确定。
- MCP remote transport 与自定义版本化 HTTP/RPC 网关的认证、取消和可观察性差异需要 spike。
- A/B 节点认证首版使用 mTLS、预配节点密钥还是短期签名 token，需要威胁建模后决定。
- 本地 Web UI 采用轻量服务端渲染还是独立前端，需要根据流式轨迹和打包体验验证。
- 长期记忆哪些事实允许模型自动建议、哪些必须由用户显式确认，需要在交互原型中确定。
- 服务可达性探测允许的协议、超时和数据读取上限需要安全评审。
