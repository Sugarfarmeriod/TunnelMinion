## Context

`IncidentInvestigator` 已经具备单 Agent 有界循环、结构化模型响应、工具参数校验、预算、取消、证据引用、冲突检查和 SQLite incident 持久化。远端路径通过认证 Gateway 做身份与能力预检，但当前证据路径仍是按事件类型写死的工具名元组；远端 run 会把后续工具统一路由到目标节点，重启恢复也只把 run 标为 `interrupted`，随后显式重跑会重新开始取证。

首个纵切选择 Windows 请求端调查 macOS `local_only`。已有节点摘要包含目标 WireGuard 状态，监听结果包含 PID/进程名与绑定地址，因此不需要为了四类语义证据机械增加四次工具调用；真正缺失的是由 Windows 请求端独立执行的目标私网端口探测，以及能够保存语义证据覆盖和执行位置的调查状态。

## Goals / Non-Goals

**Goals:**

- 用一个版本化 `service.local-only` Skill 取代该事件的硬编码工具路径，并保留其他事件的既有行为。
- 在同一调查中安全组合目标节点只读取证与请求节点只读探测。
- 持久化足以显式恢复的调查状态，跳过已经成功覆盖的证据要求。
- 由程序核验四类必要证据、冲突和停止条件，模型只在当前允许步骤中选择下一项并组织公开报告。
- 冻结旧基线并生成同口径、带分子分母和失败轨迹的新报告与隔离演示。

**Non-Goals:**

- 不引入 LangGraph、MCP、多 Agent/A2A 或新的运行时依赖。
- 不串联任何写操作，不修改 WireGuard、防火墙、路由、DNS、生产服务或现有端口进程。
- 不扩展第二个 Skill，不恢复 packet relay、复杂 Provider、自动组网或界面 showcase。
- 不把一次固定矩阵结果表述为线上效果或普遍成功率。

## Decisions

### 1. Skill 是不可执行的版本化数据契约

新增 Pydantic 契约描述 `id`、`version`、匹配事件、适用拓扑/平台、语义证据要求、每步执行位置、允许工具、确认/未知条件和输出 schema。首版只注册 `service.local-only@1`，使用代码内不可变常量；当前只有一个可信 Skill，不增加文件发现、插件加载或配置热更新。

每个证据要求拥有稳定 ID，并声明 `requester` 或 `target` 执行位置。一个工具结果可以覆盖多个语义要求：目标 `get_node_summary` 覆盖私网状态，目标 `list_network_listeners` 同时覆盖进程和监听，Windows 请求端 `probe_service_reachability` 覆盖可达性。

被否决方案：把“一项证据”直接等同于“一次工具调用”。这会重复读取节点和进程信息，并让评测奖励不必要调用。

### 2. 继续使用现有循环，先明确状态再评估 LangGraph

`IncidentInvestigator` 继续作为唯一调度边界，增加持久化 `InvestigationState`，包含 Skill 身份、run 阶段、模型/工具预算计数、证据步骤、规范化公开 facts、unknowns、停止原因和更新时间。状态随 incident 一起写入现有 SQLite JSON，不新增数据库或第二套 checkpoint。

恢复只在用户或现有调度器显式调用时发生；程序根据成功步骤跳过已覆盖证据，并用规范化 facts 重建模型公开上下文。进行中的模型或工具调用不会自动重放，未写成成功步骤的调用可以在新 run 中重新尝试。远端身份与能力预检是每次 run 的安全校验，可以在恢复时重跑；它不算重复 Skill 证据步骤，已保存成功的监听、进程和请求端探测不会重跑。

被否决方案：立即迁移 LangGraph。当前问题是状态字段和执行位置未定义；先换图框架不会自动补齐这些语义，还会扩大回归面。状态迁移稳定后再用可测收益决定是否迁移。

### 3. Harness 按执行位置复用两个既有 Runtime

目标步骤继续使用认证 Gateway 预检返回的 registry/executor；请求端步骤使用构造 Investigator 时已有的本地 registry/executor。Harness 每轮只向模型暴露当前未覆盖且依赖满足的 Skill 工具，并由程序选择对应 executor。请求端探测参数只能来自已验证目标节点摘要中的私网地址和 incident 端口。

远端离线、无权限或身份不匹配时失败关闭；不得回退成本机目标证据。请求端探测是 Skill 明确要求的独立证据，不算“误用本机工具”，其他本机监听/进程工具仍禁止用于证明远端对象。

### 4. `local_only` 的确认由确定性证据门控制

只有以下语义事实同时成立且互不冲突时才允许 `confirmed`：目标进程存在；目标端口仅绑定回环；目标私网/WireGuard 可用；从请求端探测目标私网地址与端口失败。任一必要事实缺失、不可用或冲突时，最终状态为 `insufficient_evidence`，报告保留 facts 与 unknowns。

模型可以选择下一个允许证据步骤、更新候选解释并撰写结论，但不能改变 Skill、执行位置、工具参数、证据覆盖和终态门禁。

### 5. 基线和新报告都保存可计算口径

旧 `101377a` 结果作为不可变基线清单引用，不修改历史 JSON。新 scorer 版本显式写入报告，并为比率保存 numerator、denominator 和 value。新增证据覆盖率、重复成功步骤调用率和证据不足过早停止率；前后比较必须固定 dataset/hash、模型、prompt、工具版本、预算、scorer 和重复次数，一次只比较本 change 的机制。

隔离演示复用固定数据集、内存 Gateway 和本地 Tool Runtime，输出一份人可读 JSON；它不读取实时机器状态，不需要密码或提权。

## Risks / Trade-offs

- [Incident JSON 增加状态字段可能影响旧记录] → 新字段提供默认值并加入旧 JSON 往返测试，不重写已有数据库。
- [规范化 facts 不足以恢复模型上下文] → 只保存 Skill 判定所需的有界公开字段，并用恢复测试证明成功步骤不重跑且结论一致。
- [混合执行位置可能放宽本机工具边界] → 仅允许 Skill 声明的请求端探测工具，参数来自目标摘要；监听、进程和其他本机结果仍不得证明远端对象。
- [新指标与旧报告字段不可直接比较] → 旧指标只引用冻结清单；新指标使用新 scorer 版本和明确计数，不回填或改写旧报告。
- [单次真实模型结果波动] → 开发先用固定 scripted 数据验证机制；真实模型比较必须固定配置并记录重复次数，不预设提升数字。

## Migration Plan

1. 加入向后兼容的 Skill/State 契约和旧 incident 往返测试。
2. 只将 `local_only` 接到新路径，其他事件继续使用现有证据路径。
3. 增加混合执行与恢复测试，再扩展 scorer 和数据集。
4. 先运行 scripted 隔离演示和全量回归；真实模型与 A/B 验收只在不需网络变更、提权或生产写入时执行。
5. 回滚时删除新 Skill 路由并忽略可选 state 字段；历史基线与旧 incident 仍可读取。

## Open Questions

- LangGraph 是否能在后续多个 Skills 出现后减少手写状态迁移，将由状态机复杂度和恢复缺陷数据决定，本 change 不作结论。
- MCP 只有在出现真实外部工具接入对象后再做薄适配实验，本 change 不实现。
