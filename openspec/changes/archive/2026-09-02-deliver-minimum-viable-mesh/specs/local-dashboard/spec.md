## ADDED Requirements

### Requirement: 每个 Agent 提供仅本机可访问的面板

Agent SHALL 托管本地 Web 面板及其 API，并且默认只监听 IPv4 和 IPv6 环回地址。MVP MUST NOT 提供从物理局域网、虚拟网络或公网直接访问该管理面板的监听配置。

#### Scenario: 从本机打开面板

- **WHEN** 用户在 Agent 所在设备上访问面板地址
- **THEN** Agent 返回 Web UI，并允许其读取本机聚合的节点、网络和服务状态

#### Scenario: 从另一节点访问管理端口

- **WHEN** 远端设备尝试通过本机物理地址或虚拟地址连接管理面板端口
- **THEN** 连接不可用，因为服务未绑定这些非环回地址

### Requirement: 面板展示本机和远端节点

面板 MUST 展示当前节点以及协调网络中已知的其他节点，并至少显示节点名称、在线状态、虚拟地址和当前连接路径。

#### Scenario: 三个节点均在线

- **WHEN** A、B、C 已加入同一协调网络且状态已同步
- **THEN** 任一节点的本地面板均显示 A、B、C，并区分当前节点和远端节点

#### Scenario: 远端节点离线

- **WHEN** 一个已知远端节点超过离线阈值未更新状态
- **THEN** 面板将其显示为离线，而不是从历史视图中无提示消失或继续显示为可用

### Requirement: 面板按节点展示服务目录

面板 SHALL 将活动服务按所属节点组织，并显示服务名称或可靠回退名称、类型、协议、地址、端口、可访问性和新鲜度。远端提供的文本 MUST 作为不可信纯文本渲染。

#### Scenario: 显示已识别的 Docker Web 服务

- **WHEN** 远端节点目录包含具有容器名称和可访问 HTTP 地址的服务
- **THEN** 面板在该节点下显示容器或服务名称、HTTP 类型、虚拟地址和端口

#### Scenario: 显示未知服务

- **WHEN** 服务只有协议和端口而无法可靠识别名称
- **THEN** 面板使用明确的“未知服务”回退名称，并继续显示协议、设备和端口信息

### Requirement: 面板提供与服务类型匹配的操作

对于标记为可访问的 HTTP/HTTPS 服务，面板 MUST 提供打开链接；对于其他可访问服务，面板 MUST 提供复制连接地址的操作；对于 `local-only` 或离线服务，面板 MUST 禁用远端打开操作并解释原因。

#### Scenario: 打开远端 HTTP 服务

- **WHEN** 用户点击一个在线且可从虚拟网络访问的 HTTP/HTTPS 服务
- **THEN** 浏览器打开由受管虚拟地址、端口和已识别 scheme 组成的 URL

#### Scenario: 复制游戏或数据库地址

- **WHEN** 用户对一个非 Web 的可访问服务选择复制地址
- **THEN** 面板复制规范化的虚拟 `host:port`，并向用户显示成功反馈

#### Scenario: 尝试访问仅本机服务

- **WHEN** 用户在远端节点条目中查看一个 `local-only` 服务
- **THEN** 面板不提供误导性的打开链接，并说明该服务当前只监听所属设备本机

### Requirement: 面板显示故障和数据新鲜度

面板 MUST 区分协调服务离线、网络配置失败、peer 不可达、服务目录过期和扫描降级状态。错误信息 SHALL 包含用户可理解的摘要，并允许查看不含秘密的诊断细节。

#### Scenario: 协调服务离线但隧道仍工作

- **WHEN** Agent 无法连接协调服务但已有 peer 隧道仍然可用
- **THEN** 面板分别显示“控制面离线”和仍然可用的 peer 状态，不把整个系统笼统显示为离线

### Requirement: 三端提供一致核心体验

Windows、macOS、Linux 面板 MUST 使用相同的信息架构、状态术语和核心操作；平台特有诊断可以不同，但不得缺少节点、网络和服务的核心视图。

#### Scenario: 在不同平台打开面板

- **WHEN** 用户分别在 Windows、macOS 和 Linux 节点打开相同版本的面板
- **THEN** 三端均提供节点列表、连接状态、服务目录、打开链接和复制地址等核心能力
