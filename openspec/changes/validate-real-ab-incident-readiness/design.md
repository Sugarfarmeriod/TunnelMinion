## Context

仓库已有 `run_managed_node_runtime_ab_acceptance.py`，其默认行为只打印授权面，显式执行时使用隔离 Coordinator、两端临时目录和常规应用入口，并记录生产状态摘要。当前缺口不是新能力，而是合入本机 incident 观察后的当前主线缺少新鲜真机证据。

## Goals / Non-Goals

**Goals:**

- 复用现有脚本验证当前主线的 Windows/macOS 常规入口与受管只读路径。
- 证明 HomeMac、生产 8082/8787、路由和防火墙可观察摘要前后不变。
- 失败或成功后都清理验收自有的临时进程、端口、目录和凭据。

**Non-Goals:**

- 不启动模型、不评价模型质量。
- 不申请管理员权限或 `sudo`，不执行 Provider/L3 写入。
- 不修改产品代码、现有 WireGuard、生产 Gateway 或其他暂停中的 OpenSpec change。

## Decisions

- 直接复用现有 A/B 验收脚本，不新增第二套 runner；它已具备显式执行开关、固定临时前缀、脱敏和 `finally` 清理。
- 8082 可离线，只要求前后状态一致；模型评估留到模型服务可用时单独执行。
- 报告保存为新的日期化文件，不覆盖历史真机证据。

## Risks / Trade-offs

- [远端依赖或环境漂移导致失败] → 保存失败报告并先验证清理，不以旧证据代替本轮结果。
- [只读系统命令权限有限] → 如实记录不可用摘要，不请求 `sudo`，也不把空输出解释为成功读取。
- [验收脚本自身回归] → 运行其定向测试与 OpenSpec strict；不扩展到全量开发。
