# TunnelMinion 三分钟演示脚本

目标观众是不熟悉 Agent 框架的项目所有者。演示展示诊断到限时共享的完整闭环，不展示或输入
API Key、Gateway token、Authorization 头、WireGuard 私钥、完整进程列表或容器正文。

## 演示前准备

1. Windows A 的本机面板监听 `127.0.0.1:8765`。
2. macOS B 的 Tool Gateway 监听 `10.77.0.1:8787`。
3. 两端模型状态均为 `available`。
4. 预先打开 [Figma 架构图](https://www.figma.com/board/8KODvoNqXZsLCHKO0J4nbU)。
5. 预先打开 [真实双机人工验收](../guide/真实双机人工验收.md) 和两份 JSON 报告。
6. 录屏前关闭包含密钥、终端历史或无关应用内容的窗口和通知。

## 0:00–0:30：一句话和边界

画面：Figma 架构图。

旁白：

> TunnelMinion 是运行在 WireGuard 私网两端的诊断与受控操作助手。FastAPI 接收请求，
> LangChain 让 Qwen 选择允许的检查工具，但真正的系统读取和操作由固定 Python 工作流执行；
> 安全策略与目标节点本机授权拥有最终决定权。模型没有 Shell，也不能自行改端口、路由或
> WireGuard 配置。

必须指到的图中节点：A 本地 FastAPI、A Agent、B Tool Gateway、Qwen、本机 SQLite/密钥环。

## 0:30–1:05：目录发现、只读诊断与候选计划

画面：Windows `/chat`，打开已有的 `get_node_summary` 对话。

操作：指出用户问题、模型回答、`permission_denied` 和程序生成的证据索引。

旁白：

> Coordinator 只告诉 A 哪个稳定节点在线、它声明了哪些能力和私有 endpoint；A 再用 120 秒
> assertion 直连 B 复核能力，工具流量不经过 Coordinator。取得监听、进程和可达性证据后，
> 用户明确选择服务、端口和时长，Qwen 只填写四段计划说明；节点、证据、L2 等级和权限由代码
> 固定。这是一份没有权限的候选计划。

备用素材：[Windows 聊天截图](../assets/acceptance/windows-chat.png)。

## 1:05–1:50：B 批准并执行

画面：B 本地待批准页面和操作状态。

操作：指出目标、访问者、服务指纹、入口端口、绝对过期时间、验证和回滚；点击批准。

旁白：

> 最终授权权在 B。批准前，B 再读一次监听身份并核对指纹；批准后只创建 TunnelMinion 自有的
> 临时 HTTP 入口，不改原服务、Docker、WireGuard、路由或防火墙。

强调：不把 `unreachable` 解释成服务一定停止，只能证明 A 的 TCP 探测失败。

## 1:50–2:30：A 验证、浏览器访问与自动到期

画面：A 验证结果、环回浏览器地址和随后变为 `expired` 的操作。

操作：打开 A 的临时环回地址，随后展示绝对到期和入口端口释放。

旁白：

> B 启动代理不算成功；A 必须用只留在内存中的临时凭据沿真实 WireGuard 路径验证。浏览器
> 访问 A 的环回桥，由桥注入请求头，token 不进 URL。租约到期后，即使模型离线，恢复器也会
> 停止并清理自有入口。

## 2:30–3:00：受管路径证据、安全与工程结论

画面：先展示 `direct` 三项联合证据和清理后的接口/端口检查，再展示 GitHub PR Checks，
随后切回架构图。

旁白：

> 受管路径只有在新鲜握手、精确 `/32` 路由和 A 发起的目标探测同时通过后才叫 direct。
> 清理也必须匹配本地账本和实时系统指纹，不能按接口名强删。L0 只读、L2 临时共享和 L3
> 网络治理走不同 Runtime；模型不能降低等级、批准或执行。禁止操作、越权、凭据泄露、
> 误删资源和假成功都是零容忍。

结束字幕：`Evidence first. Authority stays local.`
