# 受管连接恢复、人工干预与卸载

## 适用范围

本文只处理 TunnelMinion 创建并同时满足“本地所有权账本 + 实时系统指纹”的受管网络资源。
`HomeMac`、B 当前手写 `utun4`、用户 route、Murus/Windows 防火墙、Gateway `8787` 和模型
`8082` 都是用户资源，不属于自动恢复或卸载目标。

当前仓库已经实现并用 fake runner 验证 Windows/macOS Provider、配置 saga 和路径控制器，
但尚未获得真实 A/B 受管写入授权。因此现在可以运行离线门禁和只读观察，不能照本文直接在
真实 A/B 上创建、更新或删除接口。

## 状态判断

| 状态 | 含义 | 自动动作 | 人工动作 |
|---|---|---|---|
| `awaiting_authorization` | 计划安全但缺少本机 L3 批准 | 不执行 | 核对精确接口、地址、`/32` route、UDP 端口和回滚计划 |
| `degraded` | direct/relay 未验证或控制面陈旧 | 保留 static/last-known-good | 检查握手、route、目标探测和控制面新鲜度 |
| `rolling_back` | 当前 revision 失败，正在恢复父 revision | 只执行已记录步骤的逆序回滚 | 等待 verify，不要手工并发修改同一资源 |
| `manual_intervention` | 回滚也失败 | 停止后续 revision | 根据逐步回执定位残留项，只处理指纹匹配的自有资源 |
| `ownership_conflict` | 账本与实时资源不一致 | 禁止修改和删除 | 判断资源是否被用户或其他工具替换；先保全现场 |
| `offline` | 没有可验证路径 | 不猜测、不让模型改配置 | 使用现有 static 管理路径或本机控制台恢复 |

## 恢复顺序

1. 停止提交新 revision，保留失败 revision、父 revision、计划哈希和逐步回执。
2. 重新执行只读 `observe`，确认稳定接口 ID、公钥、配置哈希和系统指纹。
3. 若所有权仍匹配，按已成功步骤逆序恢复父 revision，再独立执行 `verify`。
4. 若所有权不匹配，进入 `ownership_conflict`，不得按接口名前缀或 `utunN` 名称强删。
5. 若父 revision 也不能验证，进入 `manual_intervention`；保留 static peer，避免同时失去管理路径。
6. 恢复后重新采集接口、route、监听端口和用户资源哈希，与变更前基线比较。

模型在线与否不改变上述流程。模型只能解释错误；计划、授权、执行、验证和回滚由确定性代码完成。

## 平台检查点

Windows 只处理独立的 `WireGuardTunnel$<managed-name>` 服务及其受管适配器。停止、卸载服务和
删除临时配置必须分别验证；不能把 `HomeMac.conf.dpapi` 或同名前缀服务当作自有资源。

macOS 使用独立配置目录、固定工具绝对路径和 `WG_TUN_NAME_FILE` 保存的账本映射。实际接口名
可能从一次启动到下一次启动发生变化；不能因为名称是 `utunN` 就判断归属。含 hook 或
`SaveConfig` 的配置必须拒绝。

## 卸载规则

普通数据卸载仍使用：

```shell
uv run tunnelminion uninstall --data-dir <DATA_DIR> --confirm DELETE-TUNNELMINION-DATA
```

该命令删除应用凭据和已知自有数据，但当前不会修改 WireGuard。受管网络资源只有在后续真实
验收完成并接入卸载编排后，才允许通过 Provider 的 `stop → verify → remove → verify` 流程
清理。每一步都必须同时满足：

- 目标出现在 TunnelMinion 所有权账本；
- 实时稳定 ID、公钥和系统指纹仍与账本一致；
- 目标不是 `observed-user`；
- 回执不含私钥、完整配置、认证头、用户 route 或未过滤 endpoint。

任一条件不满足都应停止并保留资源，不提供自动 `force-delete`。卸载完成后必须证明所有受管
秘密引用和临时明文已消失，同时用户资源与基线哈希不变。

## 离线门禁

```shell
uv run python scripts/run_managed_connectivity_assurance.py \
  --output evaluations/reports/managed-connectivity-assurance-2026-07-26.json \
  --check
```

该门禁覆盖地址冲突、签名篡改、跨节点重放、策略扩权、部分成功、回滚失败、所有权冲突、
控制面离线、direct 选择和 relay 不可用，并对比模型启用/禁用后的确定性网络结果。它不能替代
第 10 阶段的真实 A/B 授权、前后快照和清理证明。
