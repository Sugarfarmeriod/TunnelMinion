# TunnelMinion A/B 开发启动与运维

本文记录当前 MVP **已经实现且可以照着执行** 的启动、配置、排错、导出和卸载流程。
Windows 记为 A，macOS 记为 B；示例 WireGuard 地址分别是 `10.77.0.2` 和 `10.77.0.1`。

## 1. 安装与选择独立数据目录

两端均需 Python 3.11+ 和 `uv`。在仓库根目录执行：

```shell
uv sync --locked --all-groups
```

开发验收建议使用独立目录，避免和默认用户数据混在一起：

```powershell
# Windows A
uv run tunnelminion --data-dir .data/a --port 8765
```

```bash
# macOS B
uv run tunnelminion --data-dir .data/b --port 8765
```

两端本地面板都只监听 `127.0.0.1`。打开 `/chat`、`/resources`、`/memories` 或
`/api/docs`。首次启动会生成稳定的 `node-id`；按 `Ctrl+C` 停止。

未传 `--data-dir` 时使用当前操作系统账户的标准应用数据目录。验收和卸载时建议始终显式
传入目录，减少误认目录的可能。

## 2. 配置当前 Qwen

先启动 A 的本地面板，再在另一个 PowerShell 执行：

```powershell
$Body = @{
  endpoint = "http://10.77.0.1:8082/v1"
  model = "/Volumes/DarkAI/LLM/GGUF/Qwen/Qwen3.6-35B-A3B-Uncensored-HauhauCS-Aggressive-IQ4_XS/Qwen3.6-35B-A3B-Uncensored-HauhauCS-Aggressive-IQ4_XS.gguf"
  timeout_seconds = 60
} | ConvertTo-Json
Invoke-RestMethod -Method Put -Uri http://127.0.0.1:8765/api/model-config `
  -ContentType "application/json" -Body $Body
```

当前服务没有 API Key，所以请求体不写 `api_key`。配置接口会实际验证工具调用和结构化输出，
验证成功后才保存。复查与重新验证：

```powershell
Invoke-RestMethod http://127.0.0.1:8765/api/model-config
Invoke-RestMethod -Method Post http://127.0.0.1:8765/api/model-config/validate
```

若以后设置 API Key，完整值只进入 Windows Credential Manager 或 macOS Keychain，不进入
`model.json`、日志或导出文件。

## 3. 配置 A/B peer 和 B 的 Tool Gateway

先分别启动一次 A、B 本地面板，记录 `.data/a/node-id` 和 `.data/b/node-id`。以下以
`<A_NODE_ID>`、`<B_NODE_ID>` 表示。

在 A 生成独立应用 token 并保存 A 侧 peer 配置：

```powershell
$Token = uv run python -c "import secrets; print('tmn_'+secrets.token_urlsafe(32))"
$Token | uv run tunnelminion gateway-configure `
  --data-dir .data/a `
  --bind-host 10.77.0.2 `
  --peer-node-id <B_NODE_ID> `
  --peer-host 10.77.0.1
```

通过已存在的 SSH/WireGuard 通道把同一个 token 只经标准输入交给 B，不把它写进命令参数：

```powershell
$Token | ssh 10.77.0.1 "cd ~/Working-Env/tunnelminion-mvp && uv run tunnelminion gateway-configure --data-dir .data/b --bind-host 10.77.0.1 --peer-node-id <A_NODE_ID> --peer-host 10.77.0.2 --secret-store restricted-file"
Remove-Variable Token
```

`restricted-file` 是无图形 Keychain 会话的显式后备方案；在普通登录终端优先使用默认的
`keyring`。它保存的是 TunnelMinion 应用 token，不是 WireGuard 私钥。

在 B 启动网关：

```bash
uv run tunnelminion gateway --data-dir .data/b
```

Gateway 只使用配置中已经校验的 `10.77.0.1:8787`，不能用命令行改成通配地址。目前真实
A→B 的 `8787` 仍需 macOS 防火墙放行后完成最终验收；不要把“WireGuard 能 ping”误当成
“应用端口一定可达”。

## 4. 大白话排错顺序

按从底到上的顺序查，能避免把网络问题误判成模型问题：

1. **隧道通不通**：A 上 `ping 10.77.0.1`；只读查看 WireGuard 状态，不修改配置。
2. **Qwen 通不通**：A 上 `Test-NetConnection 10.77.0.1 -Port 8082`，再访问
   `http://10.77.0.1:8082/v1/models`。
3. **B 网关是否本机监听**：B 上 `curl -v http://10.77.0.1:8787/v1/capabilities`；未带
   token 返回 `401` 反而说明程序和端口已经响应，持续超时说明监听或防火墙仍有问题。
4. **A 能否到 8787**：A 上 `Test-NetConnection 10.77.0.1 -Port 8787`。
5. **模型配置是否通过**：调用 `/api/model-config/validate`，根据明确错误区分连接、认证、
   模型不存在、超时或能力不兼容。
6. **Docker 不可用**：这是可解释的降级，不会让 WireGuard、端口和进程工具一起失效。
7. **单节点模型失败**：资源页和只读工具应继续可用；模型不可用只阻止该节点的新 AI run。

macOS 防火墙状态可用系统界面查看，也可只读执行：

```bash
/usr/libexec/ApplicationFirewall/socketfilterfw --getglobalstate
sudo pfctl -sr
```

修改防火墙需要管理员决定，不属于 TunnelMinion 自动执行范围。

## 5. 脱敏数据导出

停止服务或确保没有正在写入的重要 run，然后执行：

```powershell
uv run tunnelminion export --data-dir .data/a --output .data/a-export.json
```

导出采用明确允许列表，只包含 Node ID、非秘密模型/网关配置、公开 checkpoint 和长期记忆。
它明确排除模型 API Key、Gateway token、WireGuard 秘密和原始工具 artifact 正文。导出后仍应
把文件当作私人诊断资料，因为公开 checkpoint 和记忆也可能包含用户自己的描述。

## 6. 完整卸载与数据清理

先按 `Ctrl+C` 停止本地面板和 Gateway，按需完成上一步导出，然后执行：

```powershell
uv run tunnelminion uninstall --data-dir .data/a `
  --confirm DELETE-TUNNELMINION-DATA
```

```bash
uv run tunnelminion uninstall --data-dir .data/b \
  --confirm DELETE-TUNNELMINION-DATA
```

卸载会先删除系统密钥环中的模型 API Key 和 peer token，再删除 TunnelMinion 已知自有文件。
它不会停止、修改或删除 WireGuard。目录中若有无关文件会保留该文件和目录；秘密目录里若出现
非预期子目录，清理会停止而不是递归误删。macOS Keychain 必须在允许访问的登录会话中清理；
若 Keychain 拒绝访问，命令会报错并保留磁盘配置，避免假装已经删干净。

## 7. 启用临时共享本机 HTTP 服务

该能力默认关闭。B 的 peer 配置必须显式加入操作允许项：

```powershell
$Token | ssh 10.77.0.1 "cd ~/Working-Env/tunnelminion-mvp && uv run tunnelminion gateway-configure --data-dir .data/b --bind-host 10.77.0.1 --peer-node-id <A_NODE_ID> --peer-host 10.77.0.2 --allowed-operation share_local_http_service --secret-store restricted-file"
```

B 使用专用端口范围启动：

```bash
uv run tunnelminion gateway --data-dir .data/b \
  --enable-safe-sharing \
  --sharing-min-port 18880 \
  --sharing-max-port 18899 \
  --sharing-max-duration 3600
```

逐次批准只能在 B 的本地页面或本地 CLI 完成：

```bash
uv run tunnelminion operation-approve --data-dir .data/b \
  --operation-id <OPERATION_ID> --valid-seconds 300
```

预授权同样只能由 B 本地创建，并必须同时填写请求 peer、服务 ID、服务指纹、端口范围、
最大持续时间和授权有效期。任一维度越界都会回到 `awaiting_authorization`，不会“差不多匹配”。

操作成功不等于代理进程已启动：A 必须沿 WireGuard 回调验证。普通浏览器不直接持有请求头；
A 的短期环回桥在内存中注入临时凭据，URL、页面、日志和导出均不显示 token。到期循环和启动
恢复器不调用模型，只清理所有权指纹匹配的自有资源。

## 8. 验收与网络前置条件

专用 Gateway 端口和临时入口端口都必须由节点所有者在现有网络策略中允许。TunnelMinion
不会自动修改 macOS 防火墙、Windows 防火墙、n2n/WireGuard ACL 或路由。看到 B 本机
`LISTEN` 但 A 连接超时，应记录为环境门禁失败，不能改成“功能已通过”。

发布前运行：

```shell
uv run python scripts/run_safe_sharing_evaluation.py
uv run python scripts/security_scan.py --root .
uv run python scripts/quality.py all
openspec validate approve-and-share-local-service --strict
```

真实模型应另跑 `scripts/run_real_safe_sharing_plan_evaluation.py`。2026-07-25 的本地 Qwen
实测在兼容 schema 下 2/2 生成成功，固定字段安全率 100%，平均约 7.7 秒；因此当前无需仅为
候选计划强制接入外部 API，但 Provider 仍可替换。
