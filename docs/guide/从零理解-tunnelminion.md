## 先用一句话理解产品

TunnelMinion 想做的是：在每台已经通过 WireGuard 连起来的电脑上运行一个本地助手，
让它使用严格受控的只读工具查看本机和对端状态，再让大模型根据这些真实证据解释问题。

它不是让模型直接操作电脑，也不是给模型一个 Shell。模型只负责判断“下一步应该查看
什么”和“证据说明了什么”；真正读取系统状态的是普通、可测试的 Python 工具。

## 一次问题会怎样流过系统

以后用户在 Windows 上问：“Mac 上的 PDF 服务为什么打不开？”系统大致按下面的顺序工作：

1. 本地页面把问题交给 FastAPI。
2. Runtime 判断这是普通资源查询，还是需要模型分析的开放问题。
3. 如果需要模型，LangChain 驱动一个有次数、时间和工具预算的 Agent 循环。
4. Qwen 只能从 Runtime 当前允许的只读工具中选择，例如查看端口或 Docker。
5. Tool Runtime 校验参数，然后在目标节点执行固定的 Python 适配器。
6. 工具把结构化证据交还给 Agent，而不是让模型读取或生成系统命令。
7. Agent 根据证据回答，并引用工具、节点、时间和 `tool_run_id`。
8. SQLite checkpoint 保存公开流程状态，使中断的工作可以安全恢复；LangChain 的 Agent
   本身运行在 LangGraph 之上，但项目不把每个普通读取动作都包装成一张复杂流程图。

关键分界是：**大模型作判断，确定性代码执行检查，安全策略拥有最终决定权。**

## 这些框架分别是干什么的

| 技术 | 大白话职责 | 在 TunnelMinion 中的位置 | 何时涉及 |
|---|---|---|---|
| Python | 整个节点程序的主体 | 所有层 | 已经使用 |
| Pydantic | 检查进出系统的数据是否符合规定 | 模型请求、工具参数、错误和配置 | 已经使用 |
| httpx | 代表程序发 HTTP 请求 | 连接 Qwen 和远端 Tool Gateway | 已经使用 |
| keyring | 把 API Key 放入系统保险柜 | Windows Credential Manager、macOS Keychain | 已经使用 |
| FastAPI | 给页面、本机程序和另一台节点提供 HTTP 入口 | 配置 API、资源 API、聊天、流式状态、Tool Gateway | 已经使用 |
| LangChain | 让模型在“思考—选工具—看结果—再判断”之间循环 | 本地只读 Agent | 已经使用 v1 `create_agent` |
| LangGraph | LangChain Agent 的底层流程运行时；未来显式表达审批流程 | Agent 循环、以后的人类审批 | 已间接使用，暂未另写复杂 StateGraph |
| SQLite | 保存本机线程、checkpoint、artifact 和长期记忆 | 本地数据层 | 已经使用 |
| MCP | 一种候选工具通信协议 | 曾用于跨节点协议比较 | MVP 已决定先用版本化 HTTP/RPC，不是当前主线 |
| LangSmith | LangChain 生态的追踪和评估平台 | 可选的开发辅助 | MVP 不依赖，先使用项目自己的评估数据 |

### 最实用的判断：什么时候才会碰到这些框架

不要按“项目进行到第几天”理解，而要按“哪类问题出现了”理解：

| 出现的问题 | 才需要的东西 | 本项目现在怎样 |
|---|---|---|
| 浏览器、桌面程序或另一台机器要通过 HTTP 找程序办事 | FastAPI | 已经需要；它承接页面、聊天、配置和远端 Gateway |
| 模型需要自己决定先查端口还是查 Docker，并根据结果继续查 | LangChain | 已经需要；它组织有限次数的只读工具循环 |
| 一个任务要跨很多步骤暂停、恢复、重试、分支，或等待人批准后再继续 | 显式 LangGraph 工作流 | 目前还不需要复杂 `StateGraph`；未来写操作和人工审批出现时再引入 |
| 程序重启后仍要找回公开进度和证据 | SQLite 与 checkpoint 契约 | 已经需要；只保存公开状态，不保存隐藏思维 |
| Windows 要安全询问 Mac 的状态 | 固定 Tool Gateway 与 WireGuard | 已经需要；不是 LangChain 或 LangGraph 替代网络协议 |
| 想比较不同提示词、模型或版本到底谁更可靠 | 评估数据与指标；以后可选 LangSmith | 下一阶段做；MVP 不先绑定外部平台 |

一句话记忆：**FastAPI 管“怎么进来”，LangChain 管“模型怎么选工具”，LangGraph 管“复杂任务怎么走和恢复”，Qwen 管“怎么理解和表达”，TunnelMinion 自己的策略与工具代码管“到底允不允许做”。**

### FastAPI 不是 Agent 框架

FastAPI 更像服务大厅。页面通过它提交配置、发起问题、取消 run、查看工具轨迹和读取资源。
它不决定模型调用哪个工具，也不负责保存 Agent 的工作流状态。

项目现在已经有 FastAPI 启动入口、模型配置、资源、聊天、线程、SSE 流式事件和远端 Tool
Gateway。Agent 也已能组合远端端口、进程、Docker 和可达性证据；剩余问题是让真实 Mac
防火墙放行 Gateway 后完成最终双机验收，而不是再增加一种 Web 框架。

### LangChain 负责 Agent 循环

LangChain 适合处理这种循环：

```text
用户问题 → 模型选择工具 → Runtime 执行工具 → 模型读取结果 → 继续或回答
```

项目是在只读工具和 Windows 真实适配器完成后才接入 LangChain 的。现在 Qwen 已经能选择
本次动态允许的工具、读取结果并继续回答；Tool Runtime 仍然掌握参数校验和最终执行权。

截至 2026-07-17，LangChain 官方的 v1 路线把 `create_agent` 作为标准 Agent 入口，旧的
`langgraph.prebuilt.create_react_agent` 已不再是推荐入口。TunnelMinion 已经基于锁定的 v1
API 完成兼容验证，没有复制旧教程的过时入口。

官方参考：

- [LangChain v1 更新](https://docs.langchain.com/oss/python/releases/langchain-v1)
- [LangChain v1 迁移指南](https://docs.langchain.com/oss/python/migrate/langchain-v1)

### LangGraph 不是“另一个 LangChain”

LangChain 和 LangGraph 不是二选一。LangChain 提供较高层的 Agent 入口；LangGraph 是它
下面更低层的工作流运行时。官方当前的 `create_agent` 本身就建立在 LangGraph 之上。

TunnelMinion 真正需要显式使用 LangGraph 的地方包括：

- 保存 thread/run 的 checkpoint；
- Runtime 重启后标记并读取中断任务；
- 流式报告每一步公开状态；
- 将来出现写操作时暂停流程，等待人工批准后再恢复；
- 明确表达 `Plan → Policy Check → Human Confirm → Execute → Verify`。

查看端口、刷新资源页面等确定性任务不会为了“用了 LangGraph”而强行画成图。

官方参考：

- [LangGraph 概览](https://docs.langchain.com/oss/python/langgraph/overview)
- [LangGraph v1 更新](https://docs.langchain.com/oss/python/releases/langgraph-v1)

## 为什么不一开始把所有框架装上

框架只能组织能力，不能替代能力本身。如果先装 LangChain 和 LangGraph，却没有可靠的
模型连接、参数校验、只读工具和安全策略，最终只能得到一个看起来像 Agent 的聊天 Demo。

当前顺序是有意安排的：

1. 先定义安全边界和数据契约。
2. 再确认真实 Qwen 能连接、能调用工具、能返回结构化结果。
3. 接着制作不依赖大模型也能独立测试的只读工具。
4. 工具稳定后，用 LangChain 让模型动态选择工具。
5. 对话变长、流程需要恢复时，引入 checkpoint 语义和 SQLite；只有更复杂的分支与审批出现时，
   才显式编写 LangGraph `StateGraph`。
6. 最后开放跨节点工具链路，完成真实 A/B 诊断。

这叫“能力驱动框架”，而不是“为了使用框架而设计产品”。

## 现在可以亲手看到什么

在项目目录执行：

```shell
uv run tunnelminion --port 8765
```

然后打开 `http://127.0.0.1:8765/chat` 使用第一张本地聊天页，或打开
`http://127.0.0.1:8765/resources` 查看不依赖大模型的真实本机状态；
`http://127.0.0.1:8765/api/docs` 则列出当前所有 HTTP 接口。聊天页支持新建、继续和删除
线程，发起、观察和取消 run。服务只绑定本机环回地址，不会直接暴露到局域网或 WireGuard
网络。

这一步可以把框架分工看得更直观：FastAPI 是“大厅和窗口”，LangChain 是带着问题去不同
窗口取材料的“办事员”，Qwen 负责判断，Tool Runtime 是不允许越权的“门卫”，SQLite 是
保存公开进度和证据的“档案室”。

## 两台机器现在是怎样连起来的

请把 Windows（A）和 Mac（B）想成两个各自完整的小办公室：

- 两边都有自己的本地页面、模型配置和六个只读检查工具；
- B 额外开一个只绑定 `10.77.0.1` WireGuard 地址的 Tool Gateway；
- A 使用单独生成的 TunnelMinion token 找 B，绝不拿 WireGuard 私钥充当应用密码；
- A 先问“你是谁、有哪些获准工具”，再按精确名称和版本调用；
- B 再检查身份、允许列表、速率、超时和结果大小，最后才把请求交给 Tool Runtime；
- 同一次调用在 A/B 两边使用相同的 `run_id` 和 `tool_run_id`，因此能把两本审计账对起来；
- B 没配置模型并不妨碍 A 读取 B 的状态，因为确定性工具不依赖模型。

“受控电话线”、两端接线规则、远端能力发现和多份证据的拼装逻辑都已完成。Mac 已向 WireGuard
网段放行 `8787`，真实 A→B 服务发现与模型故障隔离均已通过。可重复步骤、截图和脱敏轨迹见
[《真实双机人工验收》](真实双机人工验收.md)。

## 如何判断一个新库该不该引入

以后遇到新的 Agent 框架或“更先进”的名词，先问四个问题：

1. 它具体解决哪个已经出现的问题？
2. 不用它，当前代码会复杂在哪里？
3. 它是否让安全边界更清楚，而不是把行为藏在框架内部？
4. 它能否使用假模型和假工具做确定性测试？

四个问题没有清楚答案，就不因为流行而引入。

- 认知变化：Qwen 和 Windows 工具不再是两块孤立能力；LangChain 已把它们连成两轮 Agent
  循环。
- 已证明：Qwen 能选择本次动态注入的 `get_node_summary`，Tool Runtime 执行后把带
  `tool_run_id` 的不可信数据封装交还模型，模型再基于证据回答。

- 安全边界：LangChain 只负责循环编排；工具是否可见、参数是否合法和系统调用能否执行仍由

- 已补齐：Agent 现在有模型轮次、工具次数、墙钟超时和用户取消硬边界，并记录可获得的 token

- 下一观察点：把有界 Agent 接入 thread/run API 和公开流式事件后，页面才能安全地发起、观察和
  取消一次对话运行。

### 2026-07-18：本地 LangChain Agent 阶段完成

- 认知变化：FastAPI 的大厅、LangChain 的循环、Qwen 的判断和 Tool Runtime 的安全门已经连成
  一个可从 `/chat` 操作的本地产品切片。
- 已完成：thread/run API、SSE 公开事件、聊天页、线程新建/继续/删除、run 取消、有界循环、

- 安全回归：恶意工具文本不能添加未授权工具；过大结果会截断；最终事实、模型推测、未知项和
  停止原因分开返回。
- 真机结果：Qwen 用 2 个模型轮次调用 WireGuard、Docker 和对端 8082 可达性三个真实工具；
  第二次验收耗时约 17.0 秒、总计 2003 tokens、成本未知，三个证据 ID 全部精确引用。
- 发现并修复：第一次验收中 Qwen 手抄一个 `tool_run_id` 时漏了字符；现在精确证据索引由普通
  Python 代码自动生成，不再信任模型转抄标识符。
- 当前局限：线程和 run 只存在内存里，程序重启会消失；下一阶段才由 LangGraph checkpoint 与
  SQLite 负责持久化和安全恢复。

### 2026-07-18：上下文管家和本地储物柜完成

- 认知变化：模型的“记忆”不是把所有历史和工具输出一股脑塞回提示词，而是由程序先做预算、
  筛选和引用。LangChain 负责 Agent 循环，Context Builder 负责决定本轮模型实际能看到什么。
- 已完成：消息、工具说明、工具结果和长期记忆使用四份互不挪用的硬预算；近期消息优先，旧消息
  会形成有长度上限的滚动摘要，并记录四类内容实际占用的字符数。
- 大结果处理：完整工具结果先进入 SQLite 的 artifact 储物柜，模型只收到稳定 artifact ID 和与
  当前问题最相关的短片段。这样既保留原始证据，也避免几十页服务列表挤掉真正重要的对话。
- 长期记忆边界：目前只允许已经由用户确认的记忆进入上下文；秘密、实时快照和模型猜测不会因为
  “可能有用”就自动变成长期记忆。
- 下一观察点：显式接入 LangGraph checkpoint，让进程重启后能读回 thread，并把当时运行中的
  run 标成 `interrupted`，但绝不擅自重放旧工具调用。

### 2026-07-18：对话获得安全的重启恢复能力

- 认知变化：所谓 checkpoint 不是“让模型记住一切”，而是程序保存一张公开进度表。它包含
  thread、run、公开消息、工具证据引用和终态，不包含隐藏推理、取消令牌或后台任务对象。
