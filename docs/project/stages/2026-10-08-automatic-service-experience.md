# 自动精选服务与桌面应用风格

- 状态：实现完成；最终完成以 PR #108 最新 CI 通过并合并为条件
- 主写分支：`feature/automatic-service-experience`
- 基线：`978f248127dfa71efd6c0ed669bee93021ebd695`
- 对应总流程：可识别的服务与统一日常交互

## 结果与用户影响

用户不想逐个挑选检测项目，希望自动看到自己运行的 Python、Docker、自建服务，也不喜欢现有白绿风格。
本阶段先让本机可靠归属的 Docker 和 Python 服务自动进入日常列表，其他项目继续收起；采用石墨导航、
冷灰工作区、蓝色操作及更克制的间距和圆角，不增加首页栏目。

## 当前证据与缺口

采集器读取 TCP 监听、未连接的 UDP 端点及 Docker 发布端口，归属来自 PID 对应的进程和容器映射。
本机观察已经有这些事实，但现有快照和目录没有保留名称。目录协议严格校验额外字段，因此本阶段只在
本机内存快照保留展示名称，不向旧 Coordinator 协议添加字段；远端缺归属时仍未知，不宣称已全部识别。

## 范围与完成标准

- 自动展示明确归属的 TCP Docker/Python 项目，未知及普通后台项目仍可完整检索。
- 不按端口猜产品名称、不把监听等同于可访问、不改变服务身份、指纹、批准或网络权限。
- 不读取命令行、环境变量或业务正文；本机展示名称不进入 Coordinator 快照序列化。
- 同端口不同地址不能错误关联容器；Python 本进程不能被推荐为用户服务。
- 统一浅色/深色基础样式；保留窄屏、键盘、对比度与真实请求交接验收。
- 定向与完整门禁通过，截图来自隔离页面，清晰提交推送；一个实现 PR，合并后回写结果。

## 依赖与顺序

先补可靠本机归属与反例测试，再让已有服务列表自动显示结果；视觉改动复用现有 CSS 和导航，
最后一起验证服务列表、批准路径和两端正式包。不新增框架、模型请求、配置清单或生产部署。

## 实施记录与结果

本机展示名称保留在内存快照，字段排除序列化，现有 Coordinator 字段、服务身份与批准指纹不变。
Docker 名称来自容器记录，Python 只使用有 PID 归属的运行时名称；不会根据这些信息编造“照片备份”等用途。
同端口不同绑定地址不关联容器，双栈通配监听仍按原有身份归并；归属冲突时不挑选一个名字冒充已识别。

复用 CSS 和现有导航，石墨色顶栏、冷灰工作区、蓝色操作，缩小圆角与阴影；浅色/深色警告及错误文字
采用明确的可读颜色。新检查覆盖两个浏览器、五个页面及两种配色；不新增主题库、模型请求或手选清单。
