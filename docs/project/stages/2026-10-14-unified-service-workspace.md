# 程序发现与统一工作台

## 用户影响

用户不需要在总览、聊天和操作之间搬运信息，也不需要按端口号码人工查漏。选择程序后，在同一工作台提问、查看调查、处理已有请求；自动发现不调用模型。

## 范围与依赖顺序

1. 在本机临时用可执行文件位置精选自行安装的监听程序，仅保留名称，不保留路径或参数。通用 Python 脚本 `app.py` 可按需补充入口所在项目名，不把同名模块或不明确的目录当成项目。保留旧端能力协商、未知状态和全部技术清单；支持 TCP/UDP 归属及 Docker 连续端口。
2. 总览、聊天、请求合成一个工作台。程序清单与当前任务同时存在，历史地址继续有效；沿用现有事件、请求身份与确认流程。
3. 工作台默认由现有只读 Agent 在允许工具中选择，不要求用户选择技术工具。结果优先，运行与调查证据按需查看；不新增模型自动调用，不伪称所有对话都使用 Incident Skill。

MCP 尚未接入本产品；不因界面展示新增 MCP、框架、网络部署或关键词工程。Mac 测试页不自动更新。

## 完成标准

- 固定数据覆盖自行安装的普通程序、同进程 TCP/UDP、系统程序排除、权限失败、归属冲突和 Docker 连续端口，服务 ID 不变。
- 本机临时路径不进入适配器输出、快照、模型或持久化记录；旧远端不收到不支持的参数。
- Python 项目名是独立可选采集项，普通监听查询不读取；只保留最多 80 字符的目录名称，不读脚本内容。入口、服务 ID 和分组身份不因显示项目名而改变。
- 同一页面能选程序、问问题、读取调查和处理已有请求；切换请求不丢对话。进入页面或选择程序不发模型、申请或批准请求。
- 320px 与桌面截图、可访问性和双浏览器交互检查通过；既有未知请求结果保护和授权确认保留。
- 定向后端、前端全量门禁及本阶段 CI 通过，清晰提交、推送、一个实现 PR 合并并回写路线图。
