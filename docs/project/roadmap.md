# TunnelMinion 产品路线图

## 产品主线

我和朋友的服务散在好几台电脑上。每台电脑跑一个 TunnelMinion Agent，它负责三件事：

- 认出本机有哪些"自己的服务"；
- 服务打不开时查明原因，必要时把问题交给另一台电脑的 Agent 去查；
- 经主人批准后动手修好，并自己确认修好了。

朋友的电脑不用配置模型，也不用花钱，粘贴一个邀请码就能加入。

组网（WireGuard、n2n）假定已经通了；TunnelMinion 不负责组网，也不排查网络故障。

```mermaid
    S["认出服务<br/>✅"] --> M["服务地图首页<br/>✅"]
    M --> Q["问 Agent<br/>✅"]

    D --> R["动手修<br/>✅ 含跨电脑代批准"]
    R --> W["地图即工作台<br/>✅ 真机验收通过"]
    J["邀请码加入<br/>✅"] --> B["借用模型<br/>✅"]
    J --> I["机主身份与访客权限<br/>✅ 真机验收通过"]
    I --> G["网页上邀请与加入<br/>✅ 真机验收通过"]
    R --> P["主动巡检与预先允许的自动修<br/>✅ 真机验收通过"]
    R --> L["macOS 后台服务修复<br/>✅ 真机验收通过"]
    Q --> T["按问题挑工具<br/>✅ 真实模型对比完成"]
    B --> Q
    Q -.-> O["链路追踪<br/>✅"]

```

| 更多修法：重新运行和结束卡住的程序 | 主人从终端跑起来的普通程序（Node、Go 写的小服务、转发工具等）退出后，Agent 能提出"按上次的启动方式重新运行"；程序还在但卡住不响应，巡检连续 3 轮确认后能"结束再运行"，结束的一定是记录里那个进程；本来就不回应的服务不会被判卡住。主人自己装的 Windows 服务可以对单个服务授权后启停；compose 组按依赖顺序启动；修不了时给出不含密钥、可复制的步骤。2026-10-30 Windows 和 macOS 用测试程序部分真机验收通过，Windows 服务授权、管理员程序、TunnelMinion 重启后程序还在、macOS 后台服务卡住这几项还没验收 | #233、#237；设计 [`more-repair-kinds.md`](../design/more-repair-kinds.md)，验收记录在文末 |

### 下一步

路线图上规划的能力已经全部完成。下面是已知的不足：

- 本机 Qwen 在容器修复和巡检场景里，有时查完容器状态就停了，不接着读日志或提出修法（对比评测里每组约 7～8 次 / 63 次）。
- macOS 上用系统自带 Python 跑的脚本被重新运行后从地图上消失，再次卡住认不出来。
- 更多修法里还有几项没做真机验收：Windows 服务授权和撤回、以管理员身份运行的程序、TunnelMinion 重启后重新运行的
  程序还在、macOS 后台服务卡住时结束再拉起。
- Mac 运行包没有固定签名，每次换版本钥匙串都会按条目弹几次授权框；也还没有一键更新。

## 暂停与非目标

- 不做组网，也不排查 WireGuard、防火墙、路由和 DNS 的故障。
- 不修改系统自带服务、防火墙和系统设置；主人自己装的 Windows 服务，只在主人标成"是我的服务"、并对这一个服务打开授权后才启停。不提供"执行任意命令"这类修法。
- 不做游戏联机方向。
- 不为凑关键词增加多 Agent、A2A、RAG。MCP 和链路追踪之所以做，是因为它们有实际用途：外部 Agent 要调用诊断工具，跨电脑的委派也需要能被看清。
