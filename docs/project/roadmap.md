# TunnelMinion 产品路线图

## 产品主线

我和朋友的服务散在好几台电脑上。每台电脑跑一个 TunnelMinion Agent，它负责三件事：

- 认出本机有哪些"自己的服务"；
- 服务打不开时查明原因，必要时把问题交给另一台电脑的 Agent 去查；
- 经主人批准后动手修好，并自己确认修好了。

朋友的电脑不用配置模型，也不用花钱，粘贴一个邀请码就能加入。

组网（WireGuard、n2n）假定已经通了；TunnelMinion 不负责组网，也不排查网络故障。

```mermaid
flowchart LR
    S["认出服务<br/>✅"] --> M["服务地图首页<br/>✅"]
    M --> Q["问 Agent<br/>✅"]
    Q --> D["跨电脑委派<br/>✅"]
    D --> R["动手修<br/>✅ 含跨电脑代批准"]
    R --> W["地图即工作台<br/>✅ 真机验收通过"]
    J["邀请码加入<br/>✅"] --> B["借用模型<br/>✅"]
    J --> I["机主身份与访客权限<br/>✅ 真机验收通过"]
    B --> Q
    Q -.-> O["链路追踪<br/>✅"]
    Q -.-> X["MCP 对外开放<br/>✅"]
```

### 以后再说

- 机主身份真机验收发现的显示问题：
  - 对方认证失败（401）时，对端列表里的"可达"仍然显示为是。
  - 移除一台电脑后，其他电脑的审计只记了"同步名单"，没有写出移除了哪台。
  - 朋友的地图把朋友自己这台电脑也列成了"我的电脑"。
  - 朋友那边显示我的名字时用的是电脑名，应该改用机主的显示名。
- 本机的 Qwen 小模型在可用工具很多时，容易不去调用 Docker 工具；可以按问题缩小给模型的工具范围。
- 网页上点按钮完成邀请和加入（目前用命令行）。
- 主动巡检：服务挂了先提醒，或者在预先允许的范围内自动修。
- macOS 用户级后台服务（LaunchAgent）的修复。
- 机主身份的几处加固：
  - 换机主密钥时，钥匙串已经写好、数据库事务还没提交的那一刻，如果断电或进程被杀，旧机主密钥会丢。可以先给旧密钥留一份带时间戳的备份，事务提交后再删；启动时发现备份、并且数据库里的指纹对得上，就自动还原。
  - 回滚密钥时，只要一步出错就会停下，后面的密钥不再写回。可以改成每一步单独处理、全部做完后统一报错。
  - 朋友之间撞号时，目前只能等对方改名单；以后加一条手动处理的命令，并在审计里写明和谁冲突。
- 跨电脑接口的向后兼容：Gateway 的服务清单等老接口仍用严格模式解析，往里加字段旧版本就读不了，目前这类改动需要两台电脑一起升级。代批准的新接口已经改为忽略不认识的字段；老接口以后按同样方式放宽，或者按协议版本协商。

## 暂停与非目标

- 不做组网，也不排查 WireGuard、防火墙、路由和 DNS 的故障。
- 不修改系统服务、防火墙和系统设置；不提供"执行任意命令"这类修法。
- 不做游戏联机方向。
- 不为凑关键词增加多 Agent、A2A、RAG。MCP 和链路追踪之所以做，是因为它们有实际用途：外部 Agent 要调用诊断工具，跨电脑的委派也需要能被看清。
