# ADR 0005：首个临时共享使用内嵌有界 HTTP 代理

- 状态：已接受
- 日期：2026-07-24
- Change：`approve-and-share-local-service`

## 背景

TunnelMinion 已能诊断远端服务仅监听环回地址，但首个有副作用的 change 需要在不修改服务、WireGuard、路由、防火墙或 Docker 的情况下，为指定 peer 创建会自动过期的私网入口。

`spikes/sharing/http_proxy_probe.py` 比较了两类方案：

1. 复用 FastAPI、HTTPX 与 Uvicorn 的内嵌 HTTP 代理；
2. 由 TunnelMinion 生成配置并管理 Caddy、Nginx 或 Traefik 等外部代理。

Windows A 当前没有发现 Caddy、Nginx 或 Traefik。内嵌方案复用项目现有依赖，可以直接纳入 Python 生命周期、测试和安装包。真实网络验证使用隔离上游 `127.0.0.1:18880` 与专用入口 `10.77.0.2:18881`，不复用正式服务或端口。

## 决策

首个纵向切片使用内嵌有界 HTTP 代理，并强制：

- 入口只能绑定显式允许的非环回 WireGuard 私网地址；
- 上游必须是执行前重新确认的本机 HTTP 服务；
- 请求必须携带租约内有效的临时高熵凭据；
- 请求时限、上游响应大小和入口端口范围均受确定性预算限制；
- 代理生命周期由持久化操作和租约管理，重启后不自动重放写操作；
- 独立恢复器只识别并清理所有权可证明的 TunnelMinion 资源；
- 请求节点必须沿实际 WireGuard 路径验证，目标节点自报启动不等于成功。

第一版使用租约内多次有效、可主动撤销的短期令牌。浏览器通常会为 HTML、脚本、样式和图片发起多个请求，单次令牌无法支持普通网页；后续可以为敏感下载提供独立的一次性令牌能力。

## 支持范围

- 支持有界的普通 HTTP `GET` 与 `POST` 请求。
- 第一条真机验收使用小响应、无升级协议的 HTTP fixture。
- HTTPS 上游、自签名证书、WebSocket、SSE 长连接、大文件上传、任意方法和通用 TCP 转发不在首个实现承诺中。
- 代理不得修改上游服务监听地址或配置。

## 被否决的方案

### 修改上游监听地址

需要理解不同服务的配置和重启方式，会改变用户资源且难以可靠回滚。

### 修改防火墙或系统级端口转发

需要更高权限，Windows/macOS 差异大，也无法维持“只管理自身进程和租约”的窄边界。

### 首轮依赖外部代理

外部代理本身成熟，但增加安装、配置生成、进程所有权、版本兼容和卸载负担。当前没有真实的高级代理特性需求，也没有现成二进制基线。

### 通用 TCP 转发

会立即扩大到 SSH、数据库和游戏协议，授权、探测和安全语义差异显著。只有出现明确协议需求并建立专用适配器后再评估。

## 风险与后续验证

- 内嵌代理必须明确过滤逐跳请求头和响应头。
- 当前技术原型缓冲完整响应；生产实现需要维持严格大小预算，不能声称支持无界流式。
- 进程崩溃可能遗留租约记录；生产恢复器必须把“记录存在”和“资源所有权可证明”分开判断。
- A 上的真实网络验证只能证明绑定和转发机制，B 上的首个执行仍需重新采集状态并使用独立 fixture。

## 重新评估条件

当出现 WebSocket、长时间流式、大文件、复杂 TLS 或成熟产品打包需求，并且外部代理能够保持同等的资源所有权、租约、脱敏和卸载不变量时，重新比较受管外部代理。
