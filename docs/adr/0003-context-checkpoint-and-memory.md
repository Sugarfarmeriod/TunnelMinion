# ADR-0003：上下文、checkpoint 与长期记忆

- 状态：Accepted
- 日期：2026-07-18

## 背景

实时端口、旧聊天、运行进度和用户偏好具有不同的时效与删除语义。若把它们统称为 memory
并持续追加到提示词，旧状态可能覆盖新证据，大型服务列表会挤掉问题本身，秘密和模型猜测也
可能被错误长期保存。

## 决策

系统分离四类状态：

1. **实时状态**：每次从只读工具获取，是带来源与时间的证据，不自动写入长期记忆。
2. **短期上下文**：当前线程消息、滚动摘要和必要证据引用；删除线程时删除。
3. **工作流 checkpoint**：只保存公开 run 状态、预算和工具证据 ID；重启后把未完成 run 标记为
   `interrupted`，绝不自动重放旧工具。
4. **长期记忆**：只允许用户确认的节点别名、偏好、安全约束和稳定服务事实；按用户、网络和节点
   namespace 隔离，可查看、修正、单条删除和按作用域清空。

`ContextBuilder` 为消息、工具 Schema、工具结果和长期记忆设置互不借用的硬预算。大工具结果
进入独立 artifact store，模型只接收相关预览、稳定 artifact ID 和 `tool_run_id`。滚动摘要明确
标记“不得作为实时事实”。

API Key、私钥、认证头、完整系统日志、实时快照和未经确认的模型推测禁止进入长期记忆。

## 被否决的方案

- 把所有历史和工具正文无限追加到提示词：成本、延迟和旧状态冲突不可控。
- 把 checkpoint 当作隐藏思维存档：没有恢复必要，也扩大敏感数据范围。
- 模型自动决定哪些内容成为长期记忆：会把推测或提示注入固化为事实。
- 一个 SQLite 表承载所有语义：生命周期、作用域和删除边界难以验证。

## 后果

- checkpoint、artifact 和长期记忆即使都使用 SQLite，也保持独立契约。
- 恢复只恢复公开状态；用户需要主动发起新 run 才会重新查询实时系统。
- 上下文可能丢弃较旧或低相关内容，但会记录分类规模和丢弃数量，便于评估。
- 远端工具只能返回其 Schema 允许的系统元数据，不能读取对端聊天、模型配置或私人记忆。
