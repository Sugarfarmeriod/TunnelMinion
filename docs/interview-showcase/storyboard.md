# 首版面试展示脚本

## 30 秒定位

> TunnelMinion 是运行在私有组网节点上的设备与服务助手。它先给出可验证的设备、服务和访问地址；遇到不可达问题时，Agent 只能调用结构化只读工具诊断并生成无权限候选处理。任何有副作用的操作都必须由目标节点本地批准，执行后还要独立验证，并只恢复或清理由 TunnelMinion 明确拥有的资源。

首版使用中性的 PDF 服务场景：Windows 节点 A 上的用户希望访问 macOS 节点 B 上的本地 PDF 服务，但当前访问地址不可用。演示重点是安全闭环，不是游戏、模型数量或 Agent 数量。

## 三分钟主流程

| 时间 | 领域 | 现场动作 | 预期状态与证明点 | 现场失败时的兜底 |
|---|---|---|---|---|
| 0:00–0:20 | Overview | 打开设备与服务总览，定位 A、B 和 PDF 服务 | 显示证据时间、新鲜度和访问地址状态；证明无模型也能读取确定性资源 | 使用同一稳定提交的脱敏截图与 manifest，明确说明当前页面不可用 |
| 0:20–0:35 | Thread | 选择预设问题“为什么这个 PDF 服务打不开？” | 创建用户可理解的问题上下文，不触发任何写操作 | 展示录屏中的同一 Thread，并标注录制提交 |
| 0:35–1:10 | Run | 查看 Agent 调用节点、服务、端口和路径只读工具 | 只展示公开工具轨迹、状态、耗时、tool run ID 与证据引用；隐藏推理和原始敏感数据 | 切换到明确标记的离线 fixture，说明它不是本轮真实结果 |
| 1:10–1:30 | Evidence | 展开关键证据 | 说明问题来自哪个节点、服务指纹、观察时间和路径状态；模型结论不替代工具证据 | 使用脱敏 evidence manifest 与离线报告 |
| 1:30–1:50 | Operation | 查看候选处理 | 候选包含目标、风险、端口、有效期、验证与回滚；状态明确为“尚未授权” | 使用候选 Operation 截图，禁止称为已执行 |
| 1:50–2:15 | Operation | 在目标节点 B 本地确认或拒绝 | 请求节点和模型不能自批；批准对象、范围和有效期必须重新显示 | 若没有精确资源授权，只演示拒绝/未授权路径，不执行真实写入 |
| 2:15–2:35 | Evidence | 展示执行后验证 | Provider/服务验证与请求节点访问验证分离；失败进入恢复或人工处理 | 播放同一稳定提交的已授权录屏，并明确它不是当前现场执行 |
| 2:35–2:50 | Evidence | 查看访问地址和清理/恢复记录 | 成功只在独立验证后成立；撤销或到期只清理 owned resources | 展示脱敏 cleanup/rollback 证据，不把历史证据冒充本轮结果 |
| 2:50–3:00 | Summary | 用生命周期离线 SVG 收束 | 回顾“诊断 → 候选 → 批准 → 执行 → 验证 → 恢复/清理” | 若图源不可用，使用仓库内已校验 SVG，不打开外部图纸 |

## 五至十分钟技术深挖

### 1. Agent 与确定性工具边界

- Agent 负责理解问题、选择结构化工具和组织候选方案。
- 节点、端口、进程、服务和路径状态来自确定性工具。
- 模型不能生成并运行任意代码，也不能把自然语言判断写成成功证据。
- 无模型时资源、地址和已有操作控制继续可用；开放式诊断降级。

### 2. 目标节点授权

- 候选 `Operation` 在批准前没有执行权限。
- 批准时重新显示目标、风险、访问者、端口、有效期、验证和回滚。
- 请求节点、Coordinator 和模型都不能代替目标节点本地批准。
- 授权过期、撤销或范围不匹配时 fail closed。

### 3. 幂等、并发与恢复

- 幂等键、revision、资源所有权和 plan hash 防止重复执行与旧计划重放。
- 执行成功不等于任务成功；必须有 Provider verify 和独立 path/service verify。
- 中断后根据 journal/receipt 恢复，所有权不明时停止自动清理并提示人工处理。
- 只删除 TunnelMinion 明确创建且仍匹配指纹的资源。

### 4. 跨平台与降级

- Windows/macOS 使用相同 lifecycle 和状态语义，平台层只提供 probe 与 Provider/backend。
- Coordinator、模型或单端 probe 故障不会让本机确定性资源界面整体失效。
- Draft PR 的双平台 CI 只能证明该 head，不代表代码已进入 `main` 或完成真实 A/B。

### 5. 证据追踪

- 每条成果声明绑定 source SHA/PR、平台、环境、采集时间和验证方式。
- `main-verified`、`draft-pr-verified`、`planned`、`prohibited-claim` 不能混用。
- fixture、历史录屏和降级成功必须显著标注，不能计入本轮真实指标。
- 最终数字必须来自同一稳定提交上的命令、报告或获准真实环境。

## 首版明确排除

以下内容可以作为路线图或追问方向，但不能进入首版成功声明：

- A/B/C 三个独立 Agent 的直接通信、并发协调和矛盾证据仲裁；
- `Mission` 领域对象或通用多 Agent 角色编排；
- 公网 B 的邀请码入网、自动组网、n2n 或 relay；
- 本地 Qwen → DeepSeek → 百炼的 fallback、权限和额度路由；
- 未经精确资源授权的真实接口、地址、路由、Provider 写入、恢复或清理；
- 尚未合并 PR 的能力被描述为稳定 `main` 或已发布产品。
